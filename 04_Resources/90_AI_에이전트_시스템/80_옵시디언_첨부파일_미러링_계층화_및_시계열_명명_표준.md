# 🏛️ 옵시디언 첨부파일 미러링 계층화 및 시계열 엔지니어링 문서 명명 표준

> [!ABSTRACT] 📖 단일 진실 공급원(SSOT) 파일 아키텍처 헌장
> 본 문서는 대규모 기술 문서 및 시각화 산출물이 지속적으로 누적되는 엔터프라이즈 옵시디언 볼트에서 **① 첨부파일(`_attachments`)과 볼트 트리 간의 1:1 거울(Mirror) 디렉터리 아키텍처**, **② 미사용 고아 파일 비파괴 격리 보존 패턴**, **③ 다중 참조 이미지의 독립 복제 원칙**, 그리고 **④ 날짜·버전·핵심특징 중심의 시계열 엔지니어링 문서 명명 표준**을 정의한 영구 거버넌스 규격서입니다.

## 1. 1:1 볼트 미러링 첨부파일 아키텍처 (Mirroring Hierarchy Law)

### 1.1 평평한(Flat) 첨부파일 폴더의 태생적 한계
과거 `_attachments/` 직하위나 소수의 도메인 폴더(`10_회사_업무/` 등)에 이미지들을 평평하게 모아두는 방식은 다음의 치명적인 결함을 유발합니다:
1. **소유권 불명확**: 특정 차트/이미지가 어느 마크다운 문서에 종속된 것인지 탐색기에서 역추적 불가능.
2. **동명 파일명 충돌**: 서로 다른 프로젝트에서 생성된 `fig1.png`, `1_Diff_Actual_vs_Predicted.png` 등의 기본 파일명이 서로 덮어쓰이거나 엉뚱한 문서로 링크가 뒤엉킴.
3. **유지보수 및 아카이브 불가**: 특정 프로젝트나 문서를 외부에 공유하거나 이동할 때 관련 이미지를 일일이 찾아낼 수 없음.

### 1.2 1:1 볼트 거울(Mirror) 계층 구조 원칙
볼트 내 모든 마크다운(MD) 문서에서 사용되는 첨부 이미지는 **볼트의 디렉터리 경로를 그대로 따르며, 최종 하위 폴더명이 해당 마크다운 문서의 파일명(확장자 `.md` 제외)과 정확히 1:1 일치**하도록 격리 보관합니다.

$$\text{볼트 경로: } \texttt{D:\textbackslash 00\_obsidian\textbackslash\{상대폴더경로\}\textbackslash\{문서명\}.md}$$
$$\Downarrow$$
$$\text{첨부 경로: } \texttt{D:\textbackslash 00\_obsidian\textbackslash\_attachments\textbackslash\{상대폴더경로\}\textbackslash\{문서명\}\textbackslash\{이미지파일명}\}$$

#### 📂 실제 구조 예시
```text
D:\00_obsidian\
├── 02_Projects\회사_업무\20_unoUtil_모듈개발\20_curve_fit\
│   └── 2026-10-22_v3.66_CurveFit_제동_Jerk시작점_4대랜드마크위상정렬_과도분리_스노우웻지_종합개발보고서.md
│
└── _attachments\02_Projects\회사_업무\20_unoUtil_모듈개발\20_curve_fit\
    └── 2026-10-22_v3.66_CurveFit_제동_Jerk시작점_4대랜드마크위상정렬_과도분리_스노우웻지_종합개발보고서\
        ├── 00_TIRE_CURVE_PROCESS_STEP_BY_STEP_BRK.png
        ├── 01_BRK_INITIAL_TRANSIENT_AND_SLOPE_BY_TIRE.png
        └── ... (해당 문서 사용 차트 35장 전용 보관)
```

## 2. 첨부파일 라이프사이클 관리 3대 핵심 원칙

### 2.1 다중 참조(Multi-referenced) 이미지 독립 복제 원칙 (Independence Law)
- 2개 이상의 서로 다른 MD 문서에서 동일한 차트나 이미지를 참조할 경우, 공용 폴더(`_shared`)로 빼서 규칙을 이원화하지 않고 **각 해당 문서의 전용 첨부폴더에 각각 복제(Copy)하여 독립 배치**합니다.
- **공학적 Rationale**:
  - 현대 스토리지 환경에서 수십 KB ~ 수 MB 단위의 차트 이미지 복제는 용량 부담이 극히 미미합니다.
  - 특정 문서를 단독 열람, 이동, 백업, 또는 다른 저장소로 배포할 때 외부 종속성 없이 완결성을 100% 보장합니다.

### 2.2 미참조 고아(Orphaned) 파일 비파괴 안전 격리 패턴 (Non-Destructive Quarantine)
- 볼트 내 어떤 MD 문서에서도 참조되지 않는 과거 시각화 출력물이나 임시 이미지들은 **단 1바이트도 임의 삭제하지 않고, 기존 폴더 구조를 보존한 채 `_attachments/_미참조_보관/` 하위로 일괄 격리 이동**합니다.
- **효과**:
  - 새로 구성된 볼트 거울 트리는 100% 실사용 파일만 남아 극도의 청결성을 유지합니다.
  - 추후 누락된 과거 분석 데이터가 발견되더라도 원본 경로 구조 그대로 즉시 복구할 수 있습니다.

### 2.3 마크다운 링크 경로 표준화 (Full-Path Wikilink)
- 옵시디언 문서 내부에서는 볼트 루트 기준 상대 경로를 명시하는 위키링크 형식을 표준으로 사용합니다:
  ```markdown
  ![[_attachments/{볼트상대경로}/{문서명}/{이미지파일명}|{크기}]]
  ```
- 경로를 명시함으로써 옵시디언 전역에서 동일한 파일명이 존재하더라도 인덱싱 충돌이 원천 차단되며, 마크다운 렌더러가 즉시 대상 파일을 $O(1)$로 특정합니다.

## 3. 시계열 엔지니어링 문서 명명 표준 (Temporal Engineering Naming Law)

### 3.1 파일명 일반화의 결함
`10_가속_시험_타이어_커브피팅_검증보고서.md`처럼 일반적인 모듈명만 붙이면, 다음 분기나 차기 버전에 새로운 알고리즘 패치 보고서가 작성될 때 파일명이 중복되거나 버전 간 선후 관계가 모호해집니다.

### 3.2 표준 파일명 포맷
엔지니어링 모듈 개발, 알고리즘 고도화, 실측 데이터 검증 보고서는 반드시 아래 4대 메타 요소를 결합한 시계열 파일명 규격을 준수합니다:

$$\mathbf{\text{[YYYY-MM-DD]}}\_\mathbf{\text{[버전]}}\_\mathbf{\text{[모듈명]}}\_\mathbf{\text{[핵심특정알고리즘]}}\_\mathbf{\text{[문서유형]}}\text{.md}$$

| 구성 요소 | 형식 | 예시 | 필수 여부 | 역할 |
| :--- | :---: | :--- | :---: | :--- |
| **① 작성 일자** | `YYYY-MM-DD` | `2026-10-30` | **필수** | 탐색기 및 옵시디언 파일 목록에서 **시간 순서대로 자동 정렬** 보장 |
| **② 프레임워크 버전** | `vX.XX` | `v3.71`, `v3.66` | **필수** | 해당 연구/검증이 반영된 코드베이스의 릴리즈 마일스톤 특정 |
| **③ 모듈 식별자** | `PascalCase` | `Response`, `MuDrop`, `CurveFit` | **필수** | 담당 패키지/도메인 즉시 식별 |
| **④ 핵심 특정 알고리즘** | `한글/영문 조합` | `시작점탐지_WSS딜레이복원_적응형구간` | **필수** | 단순 결과 보고서가 아닌 **실제 수정·재설계된 기술 실체**를 파일명에 박제 |
| **⑤ 문서 유형** | `문서_종류` | `검증보고서`, `종합개발보고서`, `기술백서` | **필수** | 문서의 성격과 깊이 명시 |
