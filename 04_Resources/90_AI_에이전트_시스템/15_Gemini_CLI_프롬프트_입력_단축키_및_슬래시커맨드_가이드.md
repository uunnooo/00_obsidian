# ⌨️ Gemini CLI 프롬프트 입력 단축키 및 슬래시커맨드 운용 가이드

> [!ABSTRACT] 📖 개요
> 본 문서는 **Google Gemini CLI (Antigravity 에이전트)** 터미널 환경에서 작업 효율과 안전성을 극대화하기 위한 **특수 접두사(`@`, `!`, `?`), 슬래시 커맨드(`/plan`, `/rewind`), 클립보드 스크린샷 직접 주입(`Alt + V`) 및 핵심 단축키**를 집대성한 영구 지식 매뉴얼입니다.

---

## 🧭 1. 빠른 핵심 치트시트 (Quick Cheatsheet)

| 구분 | 키 / 명령어 | 주요 기능 및 용도 |
| :--- | :--- | :--- |
| **스크린샷 주입** | **`Alt + V`** | **클립보드 이미지 직접 붙여넣기** (파일 저장 없이 에러/차트 화면 즉시 전송) |
| **컨텍스트 첨부** | **`@<경로>`** | 파일 또는 소형 폴더 내용을 프롬프트에 직접 주입 (*대용량 폴더 주의*) |
| **파일 드래그** | **드래그 앤 드롭** | 파일 탐색기에서 파일을 터미널로 끌어다 놓으면 `@경로` 자동 완성 |
| **일회성 셸 실행** | **`!<명령어>`** | AI를 거치지 않고 시스템 터미널 명령어 즉시 실행 (`!git status`, `!pytest`) |
| **셸 모드 토글** | **`!` (단독 입력)** | 일반 프롬프트 ↔ 순수 셸 전용 터미널 모드 상호 전환 |
| **빠른 롤백** | **`Esc` 2회 연타** | 즉시 **/rewind 다이얼로그** 호출 (대화 기록 또는 코드 수정 이전 시점 복구) |
| **플랜 모드** | **`/plan [목표]`** | 읽기 전용으로 안전하게 코드 분석 후 구조 계획서(`plans/*.md`) 선제 수립 |
| **외부 에디터 작성**| **`Ctrl + G`** | 터미널 대신 VS Code/Vim 등 외부 에디터에서 장문 프롬프트 작성 후 제출 |
| **계획서 직접 수정**| **`Ctrl + X`** | AI가 작성한 계획서 마크다운을 외부 에디터로 열어 수정/코멘트 반영 |
| **승인 모드 순환** | **`Shift + Tab`** | `Default` ➔ `Auto-Edit` ➔ `Plan` 모드 빠른 순환 전환 |
| **줄바꿈 (Newline)** | **`Shift + Enter`** / **`Ctrl + Enter`** | 프롬프트를 전송하지 않고 다음 줄로 이동 (단일행 모드는 `\ + Enter`) |
| **작업 대기열** | **`Tab`** | AI가 작업 중일 때 다음 할 일을 큐(Queue)에 예약 등록 |
| **컨텍스트 압축** | **`/compress`** | 세션이 길어져 토큰이 비대해졌을 때 핵심 요약본으로 메모리 압축 |

## 📂 2. `@` 컨텍스트 주입 원리 및 대용량 폴더 프리징(Freezing) 방지

### ① `@` 멘션의 본래 목적: 명시적 기준선 주입 (Explicit Context Injection)
`@` 기능은 AI가 어디를 봐야 할지 모호할 때 **불필요한 탐색 비용을 없애고 즉시 핵심 코드를 정밀 타격**하도록 기준(Ground Truth)을 주입하는 용도입니다.

* **타깃 파일 확정**: `config.py`, `utils.py` 등 동명 파일 혼선을 방지하고 작업 대상 파일 직접 지정
* **인터페이스 대조**: 기준 파일(`@types/api.ts`)과 구현 파일(`@services/api.py`) 동시 주입
* **규격서 기반 개발**: 명세서(`@docs/SPEC.md`)를 기준으로 신규 함수 구현 지시
* **소규모 컴포넌트 폴더**: 파일 수가 3~5개로 압축된 독립 폴더 통째로 검토

### ② 🛑 대용량 폴더 멘션 시 프리징(멈춤 현상) 기술적 원인
입력창에 `@프로젝트루트`나 수백~수천 개 파일이 포함된 대규모 폴더를 지정하면 CLI가 멈추거나 터미널이 먹통이 되는 현상이 발생합니다:
1. **재귀적 파일 I/O 및 이벤트 루프 블로킹**:
   * 하위 디렉토리 트리를 전수 순회(Walk)하면서 파일 인덱싱 및 텍스트 파싱을 동기적으로 수행하여 UI 스레드가 락(Lock)에 걸립니다.
2. **토큰 폭발 및 직렬화 페이로드 초과**:
   * 대용량 파일들이 한꺼번에 직렬화(Serialization)되어 프롬프트 버퍼로 쏟아지며 메모리(Heap) 고갈 및 API 타임아웃이 발생합니다.

### ③ 💡 올바른 작업 가이드라인
* ❌ **비권장**: `@C:\Users\...` 또는 광범위한 루트 폴더 지정
* ⭕ **권장**:
  * **파일 1~3개 명시적 주입**: `@src/utils/parser.py`
  * **탐색 범위가 넓거나 모호할 때**: `@`를 쓰지 않고 **자연어로 목표만 전달** ➔ 에이전트가 자체 검색 도구(`grep_search`, `glob`, `list_directory`)를 활용하여 필요한 라인만 최소한으로 읽도록 위임

## 🖼️ 3. 클립보드 스크린샷 및 이미지 직접 주입 운용법

에러 팝업, 터미널 트레이스백, 데이터 시각화 차트, 웹 화면 등을 파일 저장 없이 즉시 AI에게 전달할 수 있습니다.

### ① 클립보드 이미지 다이렉트 붙여넣기 (`Alt + V`)
* **사용법**:
  1. `Win + Shift + S` (또는 캡처 도구)로 원하는 화면을 캡처 (클립보드에 이미지 복사됨).
  2. Gemini CLI 터미널 입력창에서 **`Alt + V`** 단축키 입력.
  3. 입력창에 이미지 첨부 플레이스홀더가 생성되면, 원하는 질문을 입력하고 `Enter`.
* **원리**: Windows 콘솔 터미널의 `Ctrl + V`는 순수 텍스트 전용인 경우가 많으므로, CLI 전용 단축키로 **`Alt + V`**가 네이티브 이미지 스트림을 가로채어 멀티모달 버퍼로 주입합니다.

### ② 드래그 앤 드롭 (Drag & Drop)
* 로컬에 저장된 이미지나 파일을 탐색기에서 터미널 창으로 끌어다 놓으면, CLI가 공백 이스케이프를 적용하여 자동으로 `@경로/파일명.png` 형태로 완성합니다.

## ⚡ 4. 특수 입력 접두사 (Special Input Prefixes)

| 접두사 | 동작 및 특징 | 사용 예시 |
| :--- | :--- | :--- |
| **`!<명령어>`** | 시스템 기본 셸(Bash/PowerShell)로 직통 전달하여 실행 후 CLI 복귀 | `!git status`<br>`!pytest -v` |
| **`!` (단독)** | **셸 전용 모드(Shell Mode)** 토글. 일반 터미널처럼 명령 실행 가능 | `!` 입력 후 `Enter` |
| **`?` (빈 입력창)** | 상단에 키보드 단축키 도움말 패널 토글 | `?` |
| **`\ + Enter`** | 단일 라인 프롬프트 모드에서 제출하지 않고 줄바꿈 | `목표:\` + `Enter` |
| **`Esc` 2회 연타** | 텍스트가 있을 때는 입력 전체 삭제, 비어있을 때는 **`/rewind` 다이얼로그 즉시 호출** | `Esc` `Esc` |
| **`Shift + Tab`** | 도구 승인 모드 순환 (`Default` ➔ `Auto-Edit` ➔ `Plan`) | `Shift + Tab` |

## 🛠️ 5. 핵심 슬래시 커맨드 (Slash Commands)

### ① 플랜 모드 (`/plan`) — 안전한 설계 우선주의
대규모 리팩토링이나 새로운 아키텍처 도입 시, 코드를 즉시 변경하지 않고 **읽기 전용 상태에서 계획서(`plans/*.md`)를 먼저 도출**합니다.
* `/plan <작업 내용>`: 한 줄로 플랜 모드 진입 및 분석 착수
* `/plan`: 플랜 모드로 모드만 전환 (이후 자유 대화)
* **`Ctrl + X` 연계 (최고의 생산성)**:
  * AI가 작성한 계획서가 출력되었을 때 `Ctrl + X`를 누르면 외부 에디터(VS Code 등)로 계획서 마크다운이 열립니다.
  * 순서를 수정하거나 단계를 삭제, 코멘트를 추가하고 저장·닫으면 AI가 이를 즉시 계획에 반영합니다.

### ② 안전 롤백 및 세션 관리
* **/rewind** (단축키 `Esc Esc`):
  * 파일 수정 전 또는 이전 대화 시점으로 코드와 대화 컨텍스트를 안전하게 복원합니다.
* **/compress**:
  * 세션이 길어져 토큰 소비가 많아지거나 응답 속도가 저하될 때, 이전 작업 맥락을 핵심 요약본으로 압축하여 메모리를 최적화합니다.
* **/resume** (별칭: `/chat`):
  * `/resume save <태그>`: 현재 시점 스냅샷 수동 저장
  * `/resume resume <태그>`: 특정 체크포인트로 복원
* **/copy**: 직전 AI의 최종 출력물을 시스템 클립보드로 복사합니다.
* **/clear**: 대화 컨텍스트를 완전히 비우고 새로운 세션을 시작합니다.

## ⌨️ 6. 실무 생산성 단축키 총정리

### ① 텍스트 편집 및 프롬프트 작성
* **`Ctrl + G` (외부 에디터 작성)**: 긴 프롬프트나 상세한 사양서를 작성할 때 외부 에디터를 호출하여 편하게 작성 후 CLI에 주입
* **`Ctrl + Enter` / `Shift + Enter`**: 멀티라인 줄바꿈
* **`Ctrl + U` / `Ctrl + K`**: 커서 앞/뒤 전체 라인 삭제
* **`Ctrl + Z` / `Ctrl + Shift + Z`**: 입력창 Undo / Redo

### ② 작업 제어 및 인터랙션
* **`Tab` (작업 대기열)**: AI가 도구 실행이나 생각 중일 때 다음 명령을 큐(Queue)에 예약 등록
* **`Ctrl + R` (히스토리 역방향 검색)**: 이전에 사용했던 명령어를 키워드로 검색하여 재사용
* **`Ctrl + Y` (YOLO 모드 토글)**: 모든 도구 권한을 사용자 확인 없이 전자동 승인 모드로 전환
* **`Ctrl + L`**: 터미널 화면 새로고침 (대화 메모리는 유지)

## 🚀 7. 플랜 모드 성능 최적화 및 외부 에디터 연동 프로토콜 (2026-10-18 개정)

### ① 플랜 모드 무한 로딩(행) 원인 및 모델 라우팅 최적화 (`modelRouting: false`)
대형 프로젝트 분석 시(누적 토큰 20만~28만 토큰 이상), 일반 모드는 빠른데 **플랜 모드(`/plan`)만 진입하면 스피너가 무한 회전하며 멈추는 현상**이 발생합니다.

* **원인 (Automatic Model Routing)**:
  * Gemini CLI는 기본 설정(`Auto`)에서 플랜 모드 진입 시 깊은 추론을 위해 고추론 모델인 **`gemini-3.1-pro-preview`**로 자동 전환합니다.
  * 이미 20만 토큰 이상 누적된 거대 세션에서 무거운 Preview 모델을 구동하면 첫 토큰 지연 시간(TTFT)이 수 분 이상 소요되어 터미널이 먹통이 된 것처럼 보입니다.
* **해결 조치 (Flash 단일화)**:
  * 최신 **`gemini-3.8-flash`** 모델은 이전 세대 Pro 이상의 코딩 추론력을 갖추고 있으므로, 플랜 모드에서도 Flash 모델을 유지하도록 설정하여 28만 토큰 세션에서도 1~2초 만에 즉각 계획서를 도출합니다.
  * **설정 파일 경로**: `C:\Users\HANTA\.gemini\settings.json`
  ```json
  {
    "general": {
      "preferredEditor": "vscode",
      "plan": {
        "modelRouting": false
      }
    }
  }
  ```

#### 🚨 나중에 Pro 모델로 다시 되돌리는 원복(Rollback) 절차
추후 특정 초고난도 설계 작업을 위해 Pro 모델의 심층 추론(Thinking)으로 복구하고자 할 때는 언제든 아래 2가지 방법 중 하나로 10초 만에 원복할 수 있습니다:
1. **설정 파일 직접 수정**:
   * `C:\Users\HANTA\.gemini\settings.json` 파일 열기
   * `"modelRouting": false` 항목을 **`"modelRouting": true`** 로 변경하거나 해당 라인을 삭제하고 저장
2. **CLI 대화형 메뉴로 수정**:
   * 터미널 프롬프트에서 **`/settings`** 입력 ➔ `Plan Model Routing` 항목을 `Enabled`로 토글 전환

### ② 계획 조회 vs 외부 에디터 직접 편집 분리 프로토콜 (`GEMINI.md`)
플랜 모드에서 계획을 열 때 엉뚱한 빈 파일이 열리거나 불필요하게 에디터가 팝업되는 문제를 방지하기 위해 사용자 지시 목적을 명확히 구분하여 전역 지침(`C:\Users\HANTA\.gemini\GEMINI.md`)에 공식 탑재하였습니다:

| 구분 | 트리거 키워드 | 에이전트 동작 메커니즘 |
| :--- | :--- | :--- |
| **단순 계획 조회**<br>*(Chat-only View)* | `"계획 보여줘"`, `"어떻게 할 건지 요약해줘"`, `"플랜 확인"`, `"진행 상황 알려줘"` | 외부 에디터 창을 띄우지 않고, **터미널 채팅창에만** 마크다운 텍스트로 요약 출력 |
| **외부 에디터 직접 편집**<br>*(External Editor Open)* | `"계획 에디터로 열어줘"`, `"플랜 수정하게 띄워줘/열어줘"`, `"수정 계획 수정하게 보여줘"`, `"계획서 파일 열어줘"` | 1) 세션 임시 계획서(`.md`) 확보<br>2) **`code "<계획서경로>"` 자동 실행으로 VS Code 팝업**<br>3) 사용자 수정 저장(`Ctrl+S`) 후 *"수정 다 했어"* 시 변경점 즉시 반영 |

### ③ 플랜 모드 강제 프로토콜 (Plan Mode Finalization Law)
* **채팅 답변만으로 플랜 종료 금지**: 플랜 모드에서 단순히 채팅 글만 출력하고 끝내는 행위 원천 차단.
* **파일 작성 및 `exit_plan_mode` 필수 호출**: 전략 수립 즉시 `write_file`로 계획서 마크다운을 디스크에 저장하고 `exit_plan_mode` 도구를 호출하여 화면에 검토 다이얼로그를 생성함으로써, 사용자가 단축키(`Ctrl+X`, `Ctrl+G`)를 눌렀을 때 언제나 실제 계획서가 에디터에 열리도록 보장.
