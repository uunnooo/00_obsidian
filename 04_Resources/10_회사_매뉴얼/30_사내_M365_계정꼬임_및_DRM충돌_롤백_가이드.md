# 🛠️ 사내 Microsoft 365 계정 꼬임 차단 및 DRM 충돌 롤백 가이드

> ⚡ **Quick Jump**: [🔍 1. 원인 진단](#-1-주요-증상-및-원인-진단-매트릭스) · [🔐 2. 개인 계정 차단](#-2-개인-계정-자동-연동-차단-및-조직-계정-고정) · [⏪ 3. 안정 버전 롤백](#-3-office-안정-빌드-롤백-절차-drm-충돌-해결) · [🔒 4. 업데이트 잠금/해제](#-4-자동-업데이트-완전-잠금-및-향후-해제-원상복구)

> [!ABSTRACT] 📖 가이드 개요
> 사내 업무용 PC에서 Microsoft 365(Excel, PowerPoint, Word) 실행 직후 창이 즉시 닫히는 현상은 크게 **(1) 브라우저 개인 MS 계정 토큰 유입으로 인한 라이선스 오류**와 **(2) Office 최신 기능 업데이트 직후 사내 문서보안(MarkAny Document SAFER / Fasoo DRM) 모듈과의 바이너리 버전 충돌**로 발생합니다. 본 문서는 두 원인의 진단 기준과 표준 복구 명령어를 정리합니다.

---

## 🔍 1. 주요 증상 및 원인 진단 매트릭스

| 구분 | 핵심 원인 메커니즘 | 레지스트리 / 이벤트 로그 식별 지표 | 표준 해결책 |
| :--- | :--- | :--- | :--- |
| **유형 A: 개인 계정 자동 유입** | Edge 등에 로그인된 개인 MS 계정(`LiveId`)이 `OneAuth` 캐시로 유입되어 무라이선스 계정으로 전환됨 | `HKCU\...\LicensingNext\<CID>` 내 `ErrorContract = 0x3` 기록 | 개인 `OneAuth` 캐시 제거 및 `SignInOptions = 2` (조직 계정 전용) 잠금 |
| **유형 B: 사내 DRM 버전 충돌** | M365 백그라운드 자동 업데이트 직후 사내 보안 모듈(`Ma365CoreChk64.dll`, `DSP_03_201664.dll`, `f_nxa.dll`)이 신규 빌드 오프셋과 충돌 | 이벤트 뷰어 `OFFICE_MODULE_VERSION_MISMATCH` 및 예외 코드 `0xc0000005` | `OfficeC2RClient.exe`로 직전 안정 빌드 롤백 후 자동 업데이트 정책 잠금 |

## 🔐 2. 개인 계정 자동 연동 차단 및 조직 계정 고정

브라우저(Edge 등)에서는 개인 계정을 그대로 쓰더라도, **Office 데스크톱 앱에서는 회사 조직 계정(Org ID / Entra ID)만 허용**하도록 레지스트리를 고정하면 계정 꼬임이 재발하지 않습니다.

### ① Office 조직 계정 전용 모드 고정 (`SignInOptions = 2`)
PowerShell에서 아래 명령을 실행합니다 (`0`: 모두 허용, `1`: 개인 계정만, `2`: 회사/조직 계정만 허용):

```powershell
New-Item -Path "HKCU:\Software\Microsoft\Office\16.0\Common\SignIn" -Force | Out-Null
Set-ItemProperty -Path "HKCU:\Software\Microsoft\Office\16.0\Common\SignIn" -Name "SignInOptions" -Type DWord -Value 2
```

### ② 이미 유입된 개인 계정 캐시 초기화 (필요 시)
1. 모든 Office 앱 및 Teams 완전 종료
2. `Win + S` → **`자격 증명 관리자`** → **[Windows 자격 증명]**에서 개인 이메일 관련 `MicrosoftAccount:...` 항목 제거
3. `%LOCALAPPDATA%\Microsoft\OneAuth\accounts` 및 `HKCU:\Software\Microsoft\Office\16.0\Common\Identity\Profiles` 내 `*_LiveId` 항목 삭제

## ⏪ 3. Office 안정 빌드 롤백 절차 (DRM 충돌 해결)

사내 보안 프로그램(MarkAny / Fasoo DRM)은 임의로 비활성화하면 암호화 문서를 열 수 없으므로, **Microsoft 공식 Click-To-Run 클라이언트를 이용해 호환성이 검증된 직전 Office 빌드로 롤백**합니다.

### ① PowerShell 롤백 실행 명령어
> [!IMPORTANT] PowerShell 호출 연산자(`&`) 필수
> PowerShell 창(`PS C:\>`)에서는 실행 파일 경로 앞에 반드시 **`&`** 를 붙이고 인자를 따옴표로 감싸야 `/` 연산자 파싱 에러가 발생하지 않습니다.

모든 Office 창을 닫은 뒤 PowerShell에서 아래 명령어를 실행합니다 (약 3~5분 소요):

```powershell
& "C:\Program Files\Common Files\Microsoft Shared\ClickToRun\OfficeC2RClient.exe" "/update" "user" "updatetoversion=16.0.20527.20088"
```

* 주황색 **"Office 업데이트를 다운로드하는 중..."** 창이 나타나며 지정한 안정 빌드(`16.0.20527.20088`, Version 2610 등)로 교체됩니다.
* **"업데이트가 설치되었습니다"** 메시지 확인 후 엑셀 정상 구동을 확인합니다.

## 🔒 4. 자동 업데이트 완전 잠금 및 향후 해제 (원상복구)

사내 M365 환경에는 클라우드 업데이트 정책(`HKLM\SOFTWARE\Policies\Microsoft\cloud\office\16.0\Common\officeupdate`)에 **`ignoregpo = 1` (로컬 그룹 정책 무시)** 및 **`updatedeadline = 3` (3일 강제 업데이트)**가 설정되어 있습니다. 따라서 일반 메뉴 버튼이나 기본 로컬 정책만으로는 문구가 바뀌지 않으며, **클라우드 정책 값(`ignoregpo = 0`, `enableautomaticupdates = 0`) 변경과 백그라운드 동기화 스케줄러(`Office Automatic Updates 2.0`, `Office Serviceability Manager`) 일시 중지**를 함께 수행해야 완전히 잠깁니다.

### ① 자동 업데이트 완전 잠금 (롤백 직후 필수 실행)
엑셀을 모두 닫은 상태에서 PowerShell에 아래 명령을 실행합니다 (관리자 승인 창에서 **[예]** 클릭):

```powershell
Start-Process powershell -Verb RunAs -ArgumentList "-NoProfile -Command Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\cloud\office\16.0\Common\officeupdate' -Name ignoregpo -Value 0 -Type DWord -ErrorAction SilentlyContinue; Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\cloud\office\16.0\Common\officeupdate' -Name enableautomaticupdates -Value 0 -Type DWord -ErrorAction SilentlyContinue; New-Item -Path 'HKLM:\SOFTWARE\Policies\Microsoft\office\16.0\common\officeupdate' -Force | Out-Null; Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\office\16.0\common\officeupdate' -Name EnableAutomaticUpdates -Value 0 -Type DWord; Disable-ScheduledTask -TaskPath '\Microsoft\Office\' -TaskName 'Office Automatic Updates 2.0' -ErrorAction SilentlyContinue; Disable-ScheduledTask -TaskPath '\Microsoft\Office\' -TaskName 'Office Serviceability Manager' -ErrorAction SilentlyContinue"
```

* **검증 방법**: 엑셀 재실행 → 좌측 하단 **[계정]** 클릭 → 업데이트 상태에 **"이 제품은 업데이트되지 않습니다."** 문구가 표시되면 잠금 완료입니다.

### ② 향후 자동 업데이트 잠금 해제 (사내 DRM 패치 완료 후 원상복구)
1~2개월 뒤 사내 보안 솔루션 호환 패치가 배포된 이후 다시 최신 Office 업데이트를 받으려면 아래 명령으로 클라우드 정책과 스케줄러를 원상복구합니다:

```powershell
Start-Process powershell -Verb RunAs -ArgumentList "-NoProfile -Command Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\cloud\office\16.0\Common\officeupdate' -Name ignoregpo -Value 1 -Type DWord -ErrorAction SilentlyContinue; Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\cloud\office\16.0\Common\officeupdate' -Name enableautomaticupdates -Value 1 -Type DWord -ErrorAction SilentlyContinue; Remove-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\office\16.0\common\officeupdate' -Name EnableAutomaticUpdates -ErrorAction SilentlyContinue; Enable-ScheduledTask -TaskPath '\Microsoft\Office\' -TaskName 'Office Automatic Updates 2.0' -ErrorAction SilentlyContinue; Enable-ScheduledTask -TaskPath '\Microsoft\Office\' -TaskName 'Office Serviceability Manager' -ErrorAction SilentlyContinue"
```
