## 1. 빅데이터의 정의 및 핵심 속성의 다차원적 확장

빅데이터(Big Data)는 단순히 '용량이 큰 데이터'에 국한되지 않고, 기존의 데이터베이스 관리 도구로 수집, 저장, 관리, 분석하기 어려운 방대한 규모와 복잡한 구조를 지닌 데이터의 총체이자, 이를 통해 새로운 비즈니스 가치를 창출하는 기술 및 생태계 전체를 의미합니다.

### (1) 빅데이터의 본질적 속성: 3V에서 5V, 그리고 7V로의 진화

* ```text
[ 빅데이터 핵심 속성의 확장 진화 ]

        ┌────────────────────────────────────────────────────────┐
        │  3V (초기 모델)                                        │
        │  - Volume (규모) / Variety (다양성) / Velocity (속도)   │
        └───────────────────────────┬────────────────────────────┘
                                    │ (신뢰성과 수익성 요구)
        ┌───────────────────────────▼────────────────────────────┐
        │  5V (비즈니스 지향)                                     │
        │  - + Veracity (신뢰성) / Value (가치)                  │
        └───────────────────────────┬────────────────────────────┘
                                    │ (데이터 유효기간과 정확성 요구)
        ┌───────────────────────────▼────────────────────────────┐
        │  7V (현대 플랫폼 지향)                                  │
        │  - + Validity (타당성) / Volatility (휘발성)           │
        └────────────────────────────────────────────────────────┘
```

초기 빅데이터 정의: Doug Laney의 3V 모델규모 (Volume): 기술의 발전과 소셜, 모바일, IoT 디바이스의 대중화로 인해 기하급수적으로 폭증하는 데이터의 물리적 크기를 의미합니다. (단위: Terabyte → Petabyte → Exabyte).
* 다양성 (Variety): 전통적인 RDBMS에 저장되는 표 형식의 정형 데이터(Structured)를 넘어, 로그, XML, JSON 등 형태가 정해져 있지 않은 반정형 데이터(Semi-structured), 그리고 이미지, 오디오, 텍스트, 영상 등 가공되지 않은 비정형 데이터(Unstructured)를 모두 아우릅니다.
* 속도 (Velocity): 데이터가 생성되고, 수집·적재되며, 실제 실시간 스트리밍 처리를 통해 분석가에게 전달되는 전체 파이프라인의 실시간성(Real-time) 속도를 규정합니다.
* 비즈니스적 가치 추가: 5V 모델신뢰성 (Veracity): 수집된 데이터 내에 포함된 노이즈(Noise)나 이상치를 제어하고 데이터의 왜곡을 방지하여 분석 결과에 대한 타당성을 확보하는 정직한 품질적 성질입니다.
* 가치 (Value): 빅데이터가 아무리 정교하고 크더라도 실제 기업의 비즈니스적 의사결정을 지원하고 정량적인 경제적 가치나 통찰(Insight)을 이끌어내지 못한다면 무의미함을 의미합니다.
* 시스템 최적화 지향: 7V 모델정확성/타당성 (Validity): 수집된 데이터가 분석하고자 하는 특정 목적과 컨텍스트에 완벽하게 부합하며, 비즈니스 가설 검증 도구로서 적합한 성질을 가지고 있는지를 뜻합니다.
* 휘발성 (Volatility): 데이터가 수집된 이후 그 수명이 언제까지 유효한지(유효기간) 정의하는 속성입니다. 유효기간이 지난 쓸모없는 데이터를 영구 보관하지 않고 자동 폐기하는 정책 수립에 필수적입니다.

## 2. DIKW 피라미드의 메커니즘과 실무 분석

DIKW 피라미드는 데이터가 단순한 사실의 수집에서 출발하여, 최종적으로 인간과 비즈니스의 지혜로운 유연한 의사결정으로 진화하는 정보 인지적 단계를 계층적으로 정립한 모델입니다.

```text
[ DIKW 피라미드 계층 구조 ]

                             /\
                            /        Wisdom (지혜)
                           / 지     : 예측, 통찰, 종합 판단
                          /  혜  \
                         /────────   Knowledge (지식)
                        /   지식     : 규칙 발견, 일반화
                       /────────────  Information (정보)
                      /     정보      : 의미 부여, 상대적 비교
                     /──────────────── Data (데이터)
                    /       데이터      : 가공되지 않은 객관적 사실
                   └───────────────────┘
```

### (1) DIKW 계층별 핵심 정의 및 비즈니스 매핑 예시

* 데이터 (Data): 현실 세계에서 발생한 객관적인 사실이자 아직 가공되지 않은 순수한 날것(Raw-material)의 수치나 기호입니다.사례: "마트 A에서 생수 1병을 1,000원에 판매하고, 마트 B에서는 1,200원에 판매한다"라는 개별 사실들의 무작위 수집.
* 정보 (Information): 수집된 데이터 간의 관계를 분석하여 정렬, 가공, 비교 처리를 거쳐 특정한 맥락적 의미(Context)를 부여한 상태입니다.사례: "마트 A의 생수가 마트 B보다 200원 더 저렴하다"라는 상대적 격차 및 맥락의 도출.
* 지식 (Knowledge): 정제된 정보들을 체계화하고 사내 도메인 경험과 연계하여, 일반화된 유용한 패턴(Pattern)과 비즈니스적 행동 규칙(Rule)을 정립한 상태입니다.사례: "생수는 다른 가공식품에 비해 유통 가격 변동이 적고, 마트 A에서 상시 대량 구매하는 것이 원가 절감에 유리하다"라는 구매 규칙의 확보.
* 지혜 (Wisdom): 축적된 지식을 바탕으로 깊이 있는 통찰과 전사적 판단력을 발휘하여, 미래의 변화를 유연하게 예측하고 창조적인 의사결정(Decision Making)을 내리는 최고 수준의 인지 단계입니다.사례: "지속적으로 저렴한 마트 A의 생수 유통 채널과 직접 연계하여, 우리 전사 유통 프로세스 자체의 소모품 조달 최적화 시스템을 영구 구축한다"라는 거시적 전략 도출.

## 3. 빅데이터의 사회·경제적 출현 배경 및 기능적 비유

### (1) 데이터 산업의 역사적 진화 단계 (★ 신규 출제 유형)

* **데이터 처리 시대**: 컴퓨터 프로그래밍 언어를 도입하여 대용량 데이터를 빠르고 정확하게 가공하기 시작한 초기 발전 단계입니다. 분석 결과는 단순 파일 형태로 개별 보관되었습니다.
  * **EDPS(Electronic Data Processing System, 전자데이터처리시스템) 도입**: 기업들은 사내 행정의 수동 연산을 줄이기 위해 급여 계산, 회계 전표 처리 등의 기계적 수동 업무에 컴퓨터를 적극 적용하기 시작했습니다. 이 시기의 데이터는 오직 **단순 업무 처리의 대상**이었으며, 새로운 가치를 발굴하거나 전략을 수립하는 고도화된 정보 자산의 속성은 가지지 못했습니다.

### (2) 빅데이터가 급부상하게 된 3대 출현 배경

* 기술적 요인 (IT 인프라 혁신): CPU/GPU 연산 능력의 기하급수적 향상, 분산 파일 시스템(HDFS)과 클라우드 컴퓨팅(AWS 등) 기술 발달로 인해 대규모 연산 비용이 비약적으로 절감되었습니다.
* 경제적 요인 (소비자 접점의 디지털화): 소셜 네트워크 서비스(SNS), 모바일 디바이스, 무선 인터넷 센서 및 IoT 기술 보급으로 원천 데이터 자체가 매일 폭발적으로 생산되는 환경이 조성되었습니다.
* 사회적 요인 (글로벌 고도 지능 사회): 국가와 사내 행정 절차가 종이에서 디지털로 완전히 이관되고, 사물 인터넷 기반의 고도화된 초연결 경제가 일상화되었습니다.

### (2) 빅데이터의 핵심적 기능과 4대 비유 (★ 출제 확률 100%)

학자들은 빅데이터가 인류 사회에서 가지는 거대한 잠재력과 영향력을 4가지 강력한 비유적 개념으로 비즈니스에 설명합니다.

* 산업 혁명의 '석탄'(또는 석유): 증기기관을 움직였던 석탄처럼, 현대 인공지능과 머신러닝 모형을 학습시키고 새로운 비즈니스 부가가치를 창출하는 가장 핵심적인 동력 자원의 기능입니다.
* 제조업의 '철(Iron)': 자동차, 선박, 빌딩의 뼈대가 되는 철처럼, 현대 디지털 경제 생태계와 소프트웨어 서비스 전반을 지탱하는 산업의 기초 원자재로서의 기능입니다.
* 통찰의 '현미경'(또는 렌즈): 눈에 보이지 않던 미생물을 현미경으로 보게 되었듯, 사소하고 파편화된 원천 로그 데이터를 정교하게 관측하여 소비자의 숨겨진 니즈나 잠재 리스크를 시각화하고 발견해 내는 통찰적 감지 도구의 기능입니다.
* 생태계의 '플랫폼(Platform)': 수많은 교통수단과 승객이 모여 상호작용하는 기차역 플랫폼처럼, 서드파티 개발자와 비즈니스 공급자, 사용자들이 데이터를 공유하며 새로운 앱과 부가가치를 자생적으로 창출하는 인프라 비즈니스 생태계로서의 기능입니다.

## 4. 데이터 패러다임의 4대 역사적 변화

빅데이터 시대의 도래는 전통적인 통계학 및 데이터 분석의 오랜 상식과 고정관념을 송두리째 뒤흔들며 거대한 패러다임의 전면 개편을 요구하고 있습니다.

```text
[ 데이터 패러다임의 역사적 전환 ]

             과거 (전통적 분석)                  현대 (빅데이터 분석)
         ┌─────────────────────────┐         ┌─────────────────────────┐
         │ 표본 조사 (Sampling)     ├─────────►│ 전수 조사 (Census)      │
         ├─────────────────────────┤         ├─────────────────────────
         │ 인과 관계 (Causation)   ├─────────►│ 상관 관계 (Correlation) │
         ├─────────────────────────┤         ├─────────────────────────┤
         │ 사전 처리 (Pre-filtering├─────────►│ 사후 처리 (Post-parsing)│
         ├─────────────────────────┤         ├─────────────────────────┤
         │ 정밀한 질 (Quality)     ├─────────►│ 압도적인 양 (Quantity)  │
         └─────────────────────────┘         └─────────────────────────┘
```

### (1) 패러다임 변화별 세부 특징 및 기술적 함의

* 표본조사에서 전수조사(Census)로의 전환내용: 컴퓨터의 연산 속도와 저장 인프라의 한계로 인해 과거에는 모집단을 대표하는 일부 표본(Sample)만을 엄격하게 수집하여 오차를 추정했습니다.
* 변화: 이제 하둡 등의 분산 병렬 연산 플랫폼의 도입으로 모든 비정형 데이터를 한 톨도 유실 없이 수집하고 대용량 전수 조사를 고속으로 돌려 추정의 무작위 샘플링 에러율을 수학적으로 최소화합니다.
* 인과관계(Causation)에서 상관관계(Correlation)로의 전환내용: 과거 학문적 분석은 "왜(Why) 이러한 원인으로 이 결과가 나왔는가"를 설명하는 인과관계와 가설 검정에 목을 매었습니다.
* 변화: 빅데이터 세상에서는 "원인을 명확히는 몰라도, 변수 A와 변수 B가 함께 움직인다"라는 상관관계를 통해 빠르게 비즈니스 현상을 예측하고 마케팅 효율을 선제 확보하는 실용주의적 의사결정이 중심이 됩니다.
* 사전처리(Pre-filtering)에서 사후처리(Post-parsing)로의 전환내용: 저장 장치의 단가가 매우 비쌌던 시절에는 오직 RDBMS 스키마에 들어갈 수 있는 정형 데이터만 사전에 골라내어 저장하고 나머지는 버렸습니다.
* 변화: 이제는 데이터가 깨지거나 쓸모없어 보이더라도 저장소의 성능이 든든하므로 무조건 원형 그대로(Raw format) 적재해 두고, 나중에 머신러닝 학습이나 분석가 기획 목적에 맞춰 사후 파싱(Parsing) 및 정제하여 활용하는 패러다임으로 진화했습니다.
* 질(Quality)보다 양(Quantity)의 시대로의 전환내용: 오염되지 않고 편향이 완전히 통제된 소량의 무결한 고품질 데이터를 신성시했습니다.
* 변화: 사소한 측정 오차가 포함되어 있더라도, 데이터의 볼륨(양)이 압도적으로 거대해지면 소수의 노이즈와 아웃라이어가 가지는 부정적 파급력이 자연스럽게 상쇄되어 전체 예측 성능이 보장되는 빅데이터의 '양적 지배 법칙'이 상식화되었습니다.

### ② 데이터 사이언스와 조직 및 전략 거버넌스

## 1. 데이터 사이언스의 본질과 데이터 사이언티스트 역량 구조

데이터 사이언스(Data Science)는 데이터로부터 고도의 통찰(Insight)을 이끌어내기 위해 수학, 통계학, 컴퓨터 공학 등의 공학적 방법론과 비즈니스 도메인 지식을 융합한 통섭적 학문 분야입니다. 단순히 데이터를 정제하고 시각화하는 데이터 분석(Data Analysis) 영역을 넘어, 복잡한 비즈니스 현안을 해결하는 머신러닝/인공지능 모델링과 예측 설계 전체를 포괄합니다.

### (1) 데이터 사이언티스트의 하드 스킬(Hard Skill)과 소프트 스킬(Soft Skill) (★ 초빈출)

시험에서 매우 높은 확률로 출제되는 핵심 이론으로, 진정한 데이터 사이언티스트가 갖추어야 할 지식 체계는 크게 공학적 도구 사용 능력인 **하드 스킬**과 인문학적·경영학적 소양인 **소프트 스킬**의 유기적 결합으로 정의됩니다.

* ```text
[ 데이터 사이언티스트의 양대 스킬셋 구조 ]

          ┌────────────────────────────────────────────────────────┐
          │  하드 스킬 (Hard Skill) - 이성적, 공학적 영역           │
          │  - 수학 및 통계학적 지식 (정교한 이론적 모델 수립)        │
          │  - 데이터베이스 및 SQL 핸들링 기술                       │
          │  - Python, R 등 데이터 머신러닝 프로그래밍 능력          │
          │  - 대규모 분산 컴퓨팅 인프라 활용 (Hadoop, Spark 등)      │
          └───────────────────────────┬────────────────────────────┘
                                      │
                                      │ (진정한 가치 창출을 위한 융합)
                                      │
          ┌───────────────────────────▼────────────────────────────┐
          │  소프트 스킬 (Soft Skill) - 감성적, 인문학적 영역         │
          │  - 비즈니스 가치를 포착하는 날카로운 통찰력 (Insight)     │
          │  - 타 부서와 의사소통할 수 있는 협업 커뮤니케이션 능력     │
          │  - 데이터 이면에 숨겨진 인과관계를 푸는 스토리텔링         │
          │  - 해당 산업군 비즈니스 도메인에 대한 깊이 있는 이해       │
          └────────────────────────────────────────────────────────┘
```

하드 스킬 (Hard Skill)수학·통계학적 기반: 선형대수학, 미적분학, 확률론, 통계적 가설 검정 등 알고리즘 이면에 흐르는 수학적 논리를 이해하는 능력입니다.
* IT 기술 및 개발 능력: 대용량 데이터를 처리하기 위한 분산 컴퓨팅 환경에 대한 깊은 이해와 실제 알고리즘을 코드로 구현해 내는 프로그래밍 지식입니다.
* 소프트 스킬 (Soft Skill)비즈니스 도메인 지식: 데이터 자체에만 매몰되지 않고, 자신이 속한 산업의 시장 특성과 비즈니스 모델을 분석하여 실제 가치를 창출할 분석 영역을 기획하는 역량입니다.
* 전략적 통찰과 커뮤니케이션: 분석 결과를 기술 용어가 아닌 비즈니스 언어로 재정의하여 임원진과 실무자들을 설득하고 전사적인 변화를 이끌어내는 인문학적 자질입니다.

---


  * ETL(Extract, Transform, Load) : 원천 데이터로부터 필요한 데이터를 추출하여 적재하고자 하는 데이터 웨어하우스에 맞게 변환하여 적재하는 과정
  * 크롤러(Crawler) : 웹 에이전트를 이용하여 인터넷 링크를 따라다니며 방문한 사이트의 웹 페이지나 소셜 데이터 등 공개되어 있는 데이터를 수집
  * NoSQL(Not-only SQL) : 전통적인 관계형 데이터베이스와는 다르게 데이터 모델을 단순화하여 설계된 비 관계형 데이터베이스로 SQL을 사용하지 않는 DBMS와 데이터 저장장치이다.
  * 인포그래픽(Infographics) : 정보를 빠르고 분명하게 표현하기 위해 정보, 자료, 지식을 그래픽 시각적으로 표현한 것을 말한다.
  * 박스 플롯(box plot) : 박스앤위스커 플롯(상자수염플롯; box-and-whisker plot)은 데이터의 대략적인 분포와 개별적인 이상치들을 동시에 보여줄 수 있으며 서로 다른 데이터 뭉치를 쉽게 비교할 수 있도록 도와주는 시각화 기법으로 가장 널리 쓰이는 시각화 형태 중 하나이다.

## 2. 전사 데이터 분석 조직의 3대 구조적 모델 (★ 100% 출제)

기업이 분석 역량을 조직 전반에 성공적으로 정착시키기 위해서는 전사 데이터 분석 인력과 의사결정 권한을 어떻게 배치하느냐가 핵심 전략입니다. 실제 분석 조직의 지배구조(Governance) 유형은 크게 집중형, 기능형, 분산형의 3가지로 압축됩니다.

```text
[ 데이터 분석 조직의 3대 지배구조 아키텍처 ]

    ① 집중형 구조 (Concentrated)       ② 기능형 구조 (Functional)        ③ 분산형 구조 (Decentralized)
    ┌──────────────────────┐         ┌──────────────────────┐        ┌──────────────────────┐
    │     전사 분석 전담    │         │     각 현업 부서     │        │ 전사 전담 + 현업 밀착 │
    │     부서가 일괄 통제   │         │     자체 분석 수행   │        │ (인력 분산 배치/풀)  │
    └──────────┬───────────┘         └──────────────────────┘        └──────────┬───────────┘
               │ (과제 하달)                                                    │ (연계 및 지원)
    ┌──────────▼───────────┐                                         ┌──────────▼───────────┐
    │   현업A   현업B  현업C │                                         │ 현업A(분) 현업B(분)   │
    └──────────────────────┘                                         └──────────────────────┘
```

### (1) 분석 조직의 주요 의사결정권자와 전문 조직 (★ 필수 수험 암기)

* **CxO (Chief Experience Officer / Chief Executive/Data Officer)**: 전사적 분석 역량을 리드하는 최고 경영/데이터 책임자입니다.
* **DSCoE (Data Science Center of Excellence, 분석전담조직)**: 데이터 분석을 전문적으로 계획하고, 통계 모형을 고도화하며, 전사 분석 가이드라인을 수립하는 집중형 전문 조직입니다.
  * ⭐ **초핵심 시험 출제 함정 포인트**: **분석전담조직(DSCoE)**은 전사적인 자원 집중과 전문성 확보를 위해 **'집중형 구조'**와 **'분산형 구조'**에서는 반드시 필요하고 유기적으로 운영되지만, 각 현업 부서가 독자적으로 분석을 처리하는 **'기능형 구조'에서는 분석전담조직이 존재하지 않거나 작동하지 않습니다.**

## 3. 분석 준비도(Readiness) 및 성숙도(Maturity) 진단 모델

전사 분석 거버넌스를 완벽하게 기획하기 위해서는 기업의 현재 분석 역량 수준을 계량적으로 측정하여 아키텍처 상의 현주소를 진단하는 것이 급선무입니다. 이를 위해 **준비도(Readiness) 6대 영역**과 **성숙도(Maturity) 4단계**를 유기적으로 결합하여 최종 진로를 설계합니다.

### (1) 분석 준비도 (Readiness) 6대 영역 (★ 필수 암기 수험 키워드)

기업이 데이터 기반 의사결정을 실현할 인프라적, 문화적 자격 요건을 갖추었는가를 정량적으로 설문하고 정량화하는 진단 기준입니다.

* 분석 업무: 분석 대상 발굴 수준, 비즈니스 활용 빈도, 의사결정 내재화 비율.
* 인력 및 조직: 분석가 직무 정의, 전담 조직 존재 여부, 전사적 교육 지원 체계.
* 분석 기술: 최신 분석 알고리즘 활용 여부, 비정형 데이터 분석 기술 확보 상태.
* 분석 데이터: 원천 데이터의 확보 상태, 품질 통제 체계, 실시간 수집 인프라 구축 여부.
* 분석 문화: 경영진의 데이터 기반 의사결정 강력한 의지, 분석 공유와 실험 정신 장려 상태.
* 분석 인프라: 분산 저장 플랫폼 환경 구성, 원활한 샌드박스(개발 환경) 제공 여부.

### (2) 분석 성숙도 (Maturity) 4단계 수준 모델

성숙도는 조직의 소프트웨어 엔지니어링 수준을 진단하는 CMMI(Capability Maturity Model Integration) 모델을 기저로 삼아, 비즈니스 분석 성숙도가 어떻게 체계화되어 진화하는지 평가합니다.

```text
[ 분석 성숙도 4단계의 고도화 흐름 ]

                         ┌─────────────────────────┐
                         │  4단계: 고도화 (Optimization)│
                         │  - 실시간 예측, 최적화 연계  │
                         └────────────▲────────────┘
                                      │
                         ┌────────────┴────────────┐
                         │  3단계: 확산 (Diffusion) │
                         │  - 전사적 표준화, 시스템화│
                         └────────────▲────────────┘
                                      │
                         ┌────────────┴────────────┐
                         │  2단계: 활용 (Application)│
                         │  - 분석 수행, 부서별 적용 │
                         └────────────▲────────────┘
                                      │
                         ┌────────────┴────────────┐
                         │  1단계: 도입 (Introduction)│
                         │  - 분석 시작, 시범적 파일럿 │
                         └─────────────────────────┘
```

* 1단계: 도입 (Introduction): 일부 분석에 관심이 있는 부서나 담당자가 주도하여 수동적인 개별 프로젝트 형태로 분석을 처음 시도해 보는 기초 수준입니다.
* 2단계: 활용 (Application): 개별 부서 차원에서 명확한 문제를 정의하고 실제 예측 모델이나 통계 기법을 비즈니스 결과물 도출에 적극적으로 활용하는 단계입니다.
* 3단계: 확산 (Diffusion): 분석의 유용성을 입증하고 전사 차원의 공용 데이터 아키텍처를 도입하여 프로세스를 표준화하고 정형화한 단계입니다.
* 4단계: 고도화 (Optimization): 실시간 자동화 분석 및 의사결정을 비즈니스 모델 자체에 체인화하여 지속적인 서비스 최적화와 경쟁 우위를 자동 창출하는 최고의 성숙 단계입니다.

### (3) 준비도-성숙도 결합 분석 진로 매트릭스 (★ 초빈출)

두 가지 진단 지표를 X축과 Y축으로 구성하여 4사분면 맵을 그리고, 각 기업군 상황에 맞는 맞춤형 로드맵을 수립합니다.

```text
[ 데이터 분석 준비도-성숙도 진로 매트릭스 ]

           준비도 High  ┌─────────────────────────┬─────────────────────────┐
                        │  준비형 (Preparation)    │  확산형 (Diffusion)     │
                        │  - 인프라/데이터 보유   │  - 인프라 및 전사 문화  │
                        │  - 그러나 실질적 활용 부족│    모두 고도로 안정     │
                        ├─────────────────────────┼─────────────────────────┤
                        │  도입형 (Introduction)  │  정착형 (Settlement)    │
                        │  - 인프라 수준이 낮음    │  - 실무 활용도는 높음   │
                        │  - 분석 역량 극히 미비  │  - 인프라 보강 절실     │
                        └─────────────────────────┴─────────────────────────┘
            준비도 Low                           성숙도 High
                                   성숙도 Low
```

* 확산형 (Diffusion - 최상의 조건): 준비도와 성숙도가 모두 매우 높은 이상적인 기업군입니다. 전사적으로 데이터 수집 인프라가 정비되어 있고 활용 표준화 및 최적화가 완성되어 있어, 현재의 수준을 지속적으로 유지·발전시키는 전략이 핵심입니다.
* 정착형 (Settlement - 현업 활용형): 성숙도는 높으나 이를 뒷받침해 줄 체계적인 인프라, 전사적 교육 체계, 데이터 품질 관리가 부족한 실속형 기업군입니다. 우선적으로 데이터 거버넌스와 플랫폼 투자를 강화하여 기술적 인프라를 채워 넣어 주어야 합니다.
* 준비형 (Preparation - 기술 인프라 선도형): IT 인프라와 데이터 적재 수준은 고도로 세팅되어 준비도는 우수하나, 정작 이를 가지고 분석 과제를 푸는 도메인 기획이나 의사결정 프로세스가 미비하여 성숙도가 떨어지는 상태입니다. 전사적인 기획 역량 확보 및 실질적인 성공 사례(Pilot) 창출이 시급합니다.
* 도입형 (Introduction - 전방위 기초 보강형): 준비도와 성숙도가 모두 바닥인 단계입니다. 전사적으로 데이터 사이언스에 대한 교육이 필요하며, 장기 계획 수립 이전에 핵심적인 소규모 단기 비즈니스 목표부터 작게 시도해 보는 접근법이 요구됩니다.

## 4. 전사 데이터 거버넌스 체계 설계

데이터 거버넌스(Data Governance)는 기업의 비즈니스 목적을 전폭적으로 달성하기 위해 전사 자산으로서의 데이터를 정의하고, 관리 프로세스를 규격화하며, 통제 조직과 권한 체계를 마크다운 문서 형태로 공식 조율해 놓은 전사 차원의 규제 및 데이터 관리 통제 체계입니다.

### (1) 데이터 거버넌스의 5대 핵심 도메인 (Core Domain)

* 데이터 표준화: 전사적으로 유일무이하게 동일한 의미로 소통할 수 있도록 데이터 명명 규칙을 정의하는 표준 단어 사전, 표준 도메인 사전, 표준 코드 체계를 영구 빌드합니다.
* 데이터 관리 체계: 원천 데이터의 수집부터 가공, 적재, 폐기에 이르는 전체 라이프사이클 속에서 메타데이터의 입력 권한과 데이터 소유권(Data Ownership)에 대한 전사적 승인 프로세스를 제도화합니다.
* 데이터 저장소 관리: 대규모 정형 데이터가 저장되는 DW(Data Warehouse), DM(Data Mart)뿐만 아니라 비정형 원천 데이터들이 보존되는 데이터 레이크(Data Lake)의 저장 용량을 설계하고 모니터링합니다.
* 표준화 활동: 데이터 거버넌스 정책이 현업 부서에서 공기처럼 준수될 수 있도록 전사 구성원 대상 거버넌스 가이드라인 배포 및 데이터 표준 준수율 진단을 주기적으로 집행합니다.
* 데이터 품질 관리: 수집된 데이터의 오염이나 포맷 왜곡을 실시간 모니터링하고 정제하여 고품질의 신뢰성 있는 원자재 상태로 정제하는 시스템을 기획합니다.

## 0. 데이터베이스(DB) 및 데이터 웨어하우스(DW)의 핵심 체계 (★ 초빈출)

하둡 분산 시스템을 배우기 전에, 전통적인 데이터 저장 체계인 데이터베이스(DB)와 데이터 웨어하우스(DW)의 개념 및 차이점을 파악하는 것은 자격증 취득에 필수적입니다.

### (1) OLTP(Online Transaction Processing)와 OLAP(Online Analytical Processing)의 차이

데이터의 유입 성격과 기업 내 정보 활용 목적에 따라 트랜잭션 중심의 **OLTP**와 분석 중심의 **OLAP**로 명확히 나뉩니다.

* **OLTP (OnLine Transaction Processing)**:
  * 호스트 컴퓨터와 단말 간 처리를 수시로 대화형식으로 처리하는 프로세싱으로, 주로 **데이터베이스의 수시 갱신 및 트랜잭션 처리**가 주 목표입니다.
  * 현재 시점의 정밀한 최신 데이터만을 디스크 및 실시간 데이터베이스 시스템에 엄격하게 무결성을 보장하며 관리합니다.
  * 예) 은행의 예금 인출 및 이체, 편의점 매출 전표 생성, 항공권 예약 시스템.
* **OLAP (OnLine Analytical Processing)**:
  * 정보 위주의 의사결정 분석 처리를 말하며, OLTP를 통해 모인 방대한 이력 트랜잭션 데이터를 다차원적으로 비교 분석하여 제품 판매 추이, 고객 구매 성향 파악, 재무 회계 예측 등을 실행합니다.
  * 사용자가 직접 다차원의 데이터베이스 정보에 손쉽게 대화형으로 접근하여 미래 비즈니스 통찰(Insight)을 도출하게 돕습니다.
  * ⭐ **초핵심 요약**: **OLTP는 데이터 '갱신(Update/Insert)' 위주**라면, **OLAP는 대용량 데이터의 '조회(Read/Query/Select)' 위주**의 성질을 가집니다.

### (2) 데이터 웨어하우스 (DW: Data Warehouse)의 4대 본질적 특징

데이터 웨어하우스는 사용자의 의사결정을 적극적으로 지원하기 위해 사내 여러 시스템에 분산된 데이터를 공통 형식으로 추출, 변환하여 통합·적재해 놓은 전사적 정형 데이터 분석 데이터베이스입니다.

* **주제지향성(Subject-orientation)**: 데이터가 부서별 업무 처리(예: 급여, 영수증)가 아니라 고객, 제품, 부품과 같이 기업의 비즈니스 상 중요한 특정 주제를 중심으로 정렬되고 구성됩니다.
* **통합성(Integration)**: 여러 원천 시스템에서 수집된 형태가 일치하지 않는 데이터를 DW에 입력할 때 데이터 포맷을 정형화하고 일관된 코드 및 단어로 변환하여 전사적으로 통합합니다.
* **시계열성(Time-variant)**: 단순 현재 상태가 아니라 일정 기간(수개월 ~ 수개년) 동안의 변화 이력을 파악할 수 있도록 데이터를 시간 시점별 연속적인 시계열 형태로 보존합니다.
* **비휘발성(Non-volatilization)**: 데이터가 한 번 적재(Load)되면, 일괄 처리 작업(Batch ETL)에 의한 갱신 이외에는 수시로 변경되거나 임의로 삭제되지 않고 영구히 보존됩니다.

### (3) 데이터 웨어하우스 (DW)의 핵심 아키텍처 및 구성 요소

데이터 웨어하우스를 완벽히 구현하여 경영을 지원하기 위해서는 다음 요소들이 체계적으로 상호작용해야 합니다.

* **데이터 모델 (Data Model)**: 주제 중심적으로 설계된 다차원의 개체-관계형(Entity-Relation) 또는 스타 스키마 모델입니다.
* **ETL (Extract, Transform, Load)**: 다양한 내·외부 원천 소스로부터 필요한 데이터를 추출(Extract), 사내 표준에 맞게 정제·변환(Transform), DW 물리 디스크에 저장 및 적재(Load)하는 일련의 수집 파이프라인 프로세스입니다.
* **ODS (Operational Data Store)**: 실시간 또는 단기적 처리를 위해 여러 RDBMS 소스에서 추출된 원본 가공 데이터를 통합 보관하는 임시 관리 물리 데이터베이스 영역입니다.
* **DW 메타데이터 (Metadata)**: 적재된 데이터 모델에 대한 스키마 구조, 가명 규칙 및 비즈니스 데이터 흐름 정보를 기술하는 데이터들의 사전 정의 정보입니다.
* **OLAP (Online Analytical Processing)**: 다차원 데이터 조회 분석 솔루션입니다.
* **데이터마이닝 (Data Mining)**: 대용량 데이터셋에 정교한 통계 알고리즘을 적용하여 보이지 않는 패턴과 인사이트를 자동으로 이끌어내는 인공지능적 분석 기법입니다.
* **경영기반 의사결정 솔루션**:
  * **KMS (Knowledge Management System, 지식 관리 시스템)**: 사내 조직원들의 경험과 지식을 문서화하여 축적·공유하는 경영 솔루션입니다.
  * **DSS (Decision Support System, 의사 결정 지원 시스템)**: 정형화된 수학적 모델과 데이터 조회를 통해 임원들의 반정형 의사결정을 실시간 보조하는 컴퓨터 기반 시스템입니다.
  * **BI (Business Intelligence, 비즈니스 인텔리전스)**: 경영 의사결정에 직간접적으로 이바지하기 위해 원천 데이터를 분석, 요약, 가시화하여 활용하는 일련의 도구 및 전략 프로세스 전체를 말합니다.

## 1. 구조적 관점에 따른 데이터 3대 유형 분류 (★ 초빈출)

빅데이터 플랫폼을 설계할 때 가장 먼저 직면하는 과제는 유입되는 데이터의 형태적 구조를 파악하는 것입니다. 데이터는 구조화된 정밀도와 스키마 존재 여부에 따라 **정형, 반정형, 비정형** 데이터의 3가지 유형으로 엄격히 분류됩니다.

* ```text
[ 데이터 구조 정밀도에 따른 3대 분류 ]

        고 (Highly Structured) ───────────────────────────────► 저 (Unstructured)
       ┌────────────────────────┬────────────────────────┬────────────────────────┐
       │   정형 데이터 (Structured)│  반정형 데이터 (Semi-) │  비정형 데이터 (Un-)   │
       │   - 엄격한 스키마 존재   │   - 메타데이터/셀프스키마│   - 형태가 고정되지 않음│
       │   - RDBMS, CSV, 행/열  │   - JSON, XML, HTML    │   - 이미지, 영상, 오디오 │
       └────────────────────────┴────────────────────────┴────────────────────────┘
```

### (1) 데이터 유형별 구조적 특징 및 매핑 비교 매트릭스

분류 기준정형 데이터 (Structured Data)반정형 데이터 (Semi-structured Data)비정형 데이터 (Unstructured Data)개념 정의고정된 필드에 스키마(Schema)가 엄격하게 적용되어 행과 열의 격자 형태로 저장되는 데이터고정된 행과 열의 형태는 없으나, 데이터 내부에 메타데이터나 태그를 포함하여 스스로 구조를 설명하는 데이터사전에 정의된 데이터 모델이나 형태가 전혀 없고 규칙성 없이 유연하게 적재되는 데이터스키마 구조Schema-on-write (데이터를 쓸 때 정의된 포맷 규칙을 검증하고 일치해야만 적재됨)Self-describing (데이터 자체에 태그, 속성, 값의 계층형 포맷 규칙이 내포되어 저장됨)Schema-on-read (적재 단계에서는 규칙 없이 붓고, 분석 엔진으로 읽어 들일 때 형태를 해석함)데이터 형식RDB 테이블, CSV, 정형화된 스프레드시트 텍스트 등JSON, XML, HTML, YAML, 웹 로그, NoSQL 키-값 문서 등이미지(PNG, JPEG), 비디오(MP4), 오디오, 소셜 미디어 텍스트, PDF 문서 등수집 및 적재정적이고 정형화된 ETL, 관계형 쿼리(SQL)를 통해 안전하게 적재API 파싱, 웹 크롤러, 분산 메시지 큐 등을 통해 스트리밍 수집분산 파일 시스템(HDFS), 오브젝트 저장소(S3) 등에 로우(Raw) 원천 상태로 벌크 적재

## 2. 하둡 분산 파일 시스템 (HDFS) 아키텍처

하둡 분산 파일 시스템(Hadoop Distributed File System, HDFS)은 수십 테라바이트에서 수 페타바이트에 이르는 초대형 파일을 범용 저사양 서버(Commodity Hardware) 여려 대에 수평 분산 저장(Scale-out)하기 위해 고안된 마스터-슬레이브(Master-Slave) 아키텍처 기반의 분산 파일 시스템입니다.

### (1) HDFS 저장 메커니즘과 블록 분할

블록 분할 (Block-based Storage): HDFS는 단일 대용량 파일을 고정된 크기의 블록(Block) 단위로 쪼개어 여러 서버에 분산 저장합니다. 하둡 2.x 이상에서의 기본 블록 크기는 $128\text{MB}(하둡1.x는$64MB)입니다.이유: 블록 크기가 너무 작으면 메타데이터 급증으로 NameNode 메모리에 과부하가 발생하고, 너무 크면 네트워크 전송 병목이 생깁니다.
* 블록 복제 메커니즘 (Replication Factor): 데이터 유실 및 장비 장애에 대응하기 위해 각 블록을 다수의 DataNode에 중복 복제하여 보관합니다. 전사 표준 기본 설정 값은 3 (3중 복제)입니다.

```text
[ HDFS 랙 인식(Rack Awareness) 복제 알고리즘 ]

       [ Rack 1 (네트워크 스위치 A) ]                 [ Rack 2 (네트워크 스위치 B) ]
       ┌───────────────────────────┐                 ┌───────────────────────────┐
       │ ┌──────────┐ ┌──────────┐ │                 │ ┌──────────┐              │
       │ │ DataNode1│ │ DataNode2│ │                 │ │ DataNode3│              │
       │ │ [블록 A] │ │ [블록 A-1]│ │                 │ │ [블록 A-2]│              │
       │ └──────────┘ └──────────┘ │                 │ └──────────┘              │
       └───────────────────────────┘                 └───────────────────────────┘
       * 규칙: 로컬 랙에 1개 적재(DN1) -> 같은 랙의 다른 노드에 2차 복제(DN2) -> 다른 원격 랙에 3차 복제(DN3)
```

### (2) NameNode와 DataNode의 구조적 역할 관계

```text
┌───────────────────────────┐
                               │  NameNode (Master Node)   │
                               │  - 파일 시스템 네임스페이스  │

                               └─────────────┬─────────────┘

       ┌───────────────▼───────────┐ ┌───────▼───────────────────┐ ┌───▼───────────────────────┐
       │   DataNode 1 (Slave)      │ │   DataNode 2 (Slave)      │ │   DataNode 3 (Slave)      │
       │   - 로컬 디스크 블록 저장  │ │   - 로컬 디스크 블록 저장  │ │   - 로컬 디스크 블록 저장  │
       │   - 실제 데이터 읽기/쓰기  │ │   - 실제 데이터 읽기/쓰기  │ │   - 실제 데이터 읽기/쓰기  │
       └───────────────────────────┘ └───────────────────────────┘ └───────────────────────────┘
```

* NameNode (마스터)네임스페이스 관리: 디렉터리 생성, 삭제, 파일명 변경 등 전체 디스크 파일 시스템 디렉터리 트리를 관리합니다.
* 메타데이터 관리: 파일과 블록의 매핑 관계, 데이터 복제본 위치 정보를 메모리(RAM) 상에 실시간 유지합니다.
* 보존 장치: 메모리 내의 메타데이터를 백업하기 위해 로컬 디스크에 파일 시스템 스냅샷 파일인 FsImage와 실시간 트랜잭션 로그 파일인 EditLog를 기록합니다.
* DataNode (슬레이브)데이터 저장: 실제 파일을 하둡 블록 단위로 로컬 디스크 상에 저장하고 관리합니다.
* 상태 전송 (Heartbeat): 주기적으로 NameNode에 생존 신호(Heartbeat)와 블록 상태 보고서(Block Report)를 송신하여 자신의 무결성을 보고합니다.

## 3. 맵리듀스 (MapReduce) 데이터 분산 처리 아키텍처

맵리듀스(MapReduce)는 대규모 하둡 클러스터 환경에서 데이터를 고속 병렬 처리하기 위해 구글이 제안한 소프트웨어 프레임워크입니다. 모든 데이터의 흐름은 임의의 구조에서 목적을 향해 구조화되는 **Key-Value 페어(쌍)** 형태로 일관되게 설계 및 처리됩니다.

### (1) 맵리듀스의 3대 핵심 단계 연산 흐름

```text
Input Data ──► [ Map 단계 ] ──► [ Shuffle & Sort 단계 ] ──► [ Reduce 단계 ] ──► Output Data
    (HDFS 로컬 블록) (K1, V1) -> (K2, V2)   (같은 Key끼리 그룹화)    (K2, List[V2]) -> (K3, V3) (HDFS 최종 저장)
```

* Map (맵 단계)입력 데이터를 한 줄씩 읽어 들여 의미 있는 단위로 분해하고, 이를 통계 처리가 용이한 새로운 형태의 중간 (Key, Value) 쌍으로 변환하여 임시 출력하는 분할 과정입니다.
* 이 단계는 데이터가 물리적으로 보존되어 있는 노드 내부에서 직접 실행되는 데이터 로컬리티(Data Locality) 보장 원칙에 의해 네트워크 전송 오버헤드를 극도로 줄입니다.
* Shuffle & Sort (셔플 및 정렬 단계 - ★ 기술 기출)Map 단계의 결과를 수집하여, 네트워크 망을 통해 동일한 키(Key)를 가진 모든 데이터를 특정 Reduce 노드 한 곳으로 모으는 중간 네트워킹 가공 단계입니다.
* 이 과정에서 고속 집계를 위해 키 값을 오름차순 또는 내림차순으로 자동 정렬하여 (Key, List[Value]) 형태로 가공합니다. 맵리듀스 아키텍처에서 가장 전송 비용이 큰 물리적 병목 구간입니다.
* Reduce (리듀스 단계)셔플링을 통해 정렬·그룹화되어 유입된 중간 집계 데이터들의 리스트 값을 최종 합산(Sum), 평균, 필터링 연산하여 최종 산출물 데이터로 축약 및 결합하여 HDFS에 영구 적재하는 집약 단계입니다.

## 4. 하둡 에코시스템 (Hadoop Ecosystem) 주요 프레임워크 구성도

하둡은 단순한 저장과 맵리듀스 분산 연산 엔진일 뿐이며, 비즈니스 가치 창출을 완성하기 위해서는 원천 데이터를 입수하고 실시간 쿼리 및 분석을 제어하는 강력한 오픈소스 에코시스템의 통합 관리가 필수적입니다.

```text
[ 하둡 에코시스템 레이어별 컴포넌트 구조 ]

    ┌────────────────────────────────────────────────────────────────────────────────────────┐
    │  워크플로우 / 리소스 조정 (Coordination) : Oozie, ZooKeeper, YARN                       │
    ├──────────────────────────────────────────┬─────────────────────────────────────────────┤
    │  실시간 질의 및 분석 (SQL-on-Hadoop)      │  실시간 인메모리 연산 (In-Memory Processing) │
    │  - Hive, Impala, Presto, Pig             │  - Apache Spark, Spark Streaming, Storm     │
    ├──────────────────────────────────────────┴─────────────────────────────────────────────┤
    │  NoSQL / 분산 데이터베이스 (Distributed Storage) : HBase, Cassandra                       │
    ├──────────────────────────────────────────┬─────────────────────────────────────────────┤
    │  정형 데이터 수집 및 적재 (RDB to Hadoop)  │  비정형 로그 데이터 수집 (Log Ingestion)      │
    │  - Sqoop (맵온리 병렬 아키텍처)           │  - Flume (에이전트 트랜잭션 수집)            │
    ├──────────────────────────────────────────┴─────────────────────────────────────────────┤
    │  분산 물리 저장 구조 (Storage Core Layer) : HDFS (Hadoop Distributed File System)      │
    └────────────────────────────────────────────────────────────────────────────────────────┘
```

### (1) 에코시스템 컴포넌트별 아키텍처적 특성 요약

* Flume (플룸): 다수의 소스 서버로부터 비정형 로그 파일을 실시간으로 수집하여 HDFS로 전송하는 수집기입니다. Source -> Channel -> Sink로 연결되는 독립 에이전트 전송 트랜잭션을 통해 메모리 및 디스크 버퍼를 제어하여 전송 유실을 원천 차단합니다.
* Sqoop (스쿱): Oracle, MySQL 같은 전형적인 관계형 데이터베이스(RDBMS)와 Hadoop 간의 대용량 정형 데이터를 고속 양방향으로 전송(Import/Export)해 주는 매개체입니다. 내부적으로 맵리듀스의 Map-Only(Reduce 단계 없는 병렬 실행) 구조를 사용하여 유실 없이 분산 병렬 적재를 완수합니다.
* Spark (스파크): 맵리듀스가 가졌던 디스크 I/O 입출력 속도 한계를 극복하기 위해 제안된 In-Memory(인메모리) 기반의 차세대 초고속 연산 프레임워크입니다. 핵심 자료구조인 **RDD(Resilient Distributed Dataset)**를 통해 유실 시 혈통을 추적하는 계보(Lineage) 복구 기능을 지원합니다.
* Hive (하이브): Java 코딩에 익숙하지 않은 분석가들을 위해 하둡에 적재된 빅데이터를 표준 SQL 쿼리로 직접 분석할 수 있게 돕는 데이터 웨어하우스 도구입니다. 작성된 SQL 구문은 내부 컴파일러에 의해 HiveQL -> MapReduce 코드로 변환되어 하둡에서 병렬 샐행됩니다.
* HBase (에이치베이스): HDFS 물리 디스크 위에 가동되는 구글 빅테이블(Bigtable) 아키텍처 기반의 분산 칼럼 지향 NoSQL 데이터베이스입니다. HDFS의 읽기-쓰기 속도 한계를 뛰어넘어 실시간 초고속 무작위 읽기/쓰기(Random Read/Write) 성능을 원천 제공합니다.
* YARN (얀): 하둡 2.0부터 도입된 전사 차원의 클러스터 리소스 관리 리더십 전담 프레임워크입니다. 자원 관리를 전담하는 ResourceManager와 개별 분산 분석 애플리케이션의 라이프사이클을 통제하는 ApplicationMaster를 분리 설계하여 하둡 인프라의 처리량을 비약적으로 증폭시켰습니다.
* **Tajo (타조)**: HDFS 물리 디스크 분산 저장소에 보관된 데이터에 대해 SQL 형태의 명령어를 사용하여 초고속 병렬 질의 처리를 수행하는 국내 개발 대용량 데이터 웨어하우스(DW) 엔진입니다. 2010년 고려대학교 연구실에서 최초 개발되었으며 2014년 아파치 재단 최상위 프로젝트(TLP)로 승격되었습니다. 기존 대표 주자인 하이브(Hive)와 역할이 동일하나 처리 성능과 메모리 제어 편의성이 월등히 뛰어난 강점이 있습니다.
* **Oozie (우지) & WAS 서블릿**: 하둡 병렬 작업을 체계적으로 결합 및 제어하는 워크플로우 및 코디네이터 소프트웨어입니다. 이 엔진은 내부적으로 자바 서블릿 컨테이너(Java Servlet Container) 환경에서 작동하는 자바 웹 애플리케이션으로 기획되었으며, **WAS(Web Application Server)**의 관리 엔진 안에서 가동되어 맵리듀스나 피그(Pig) 등의 스텝 연산을 실행 통제합니다.

## 2. 준식별자(QID)의 정의와 연결 공격 (Linking Attack)

비식별 조치를 설계할 때 가장 강력히 통제해야 하는 대상은 단순 주민등록번호나 이름 같은 고유 식별자가 아닌, **준식별자(Quasi-Identifiers, QID)**입니다.

### (1) 준식별자 (QID)

정의: 단독으로는 특정 개인을 식별할 수 없으나, 외부의 공개된 공공 데이터셋(예: 선거인 명부, 인구조사 데이터) 등 다른 정보와 결합(Linking) 및 대조할 경우 개인을 특정해 낼 수 있는 간접 식별 속성군입니다.
* 대표 속성: 우편번호(ZIP code), 생년월일, 성별, 직업, 졸업학교 등.

### (2) 연결 공격 (Linking Attack)

* 외부 데이터와 준식별자 정보를 유기적으로 매핑하여 비식별화된 데이터 속의 주인을 다시 추적해 내는 기식별 재현 공격 기법입니다.

## 3. 3대 수학적 프라이버시 보호 모델 (★ 기출 필수 계산식)

준식별자의 결합 및 재식별 가능성을 수학적으로 정량화하고 안전성 한계(Bound)를 통제하기 위해 제안된 3대 프라이버시 보호 모델은 k**-익명성,**l**-다양성,**t**-근접성**입니다. 이 모델들은 계층적으로 이전 모델의 취약점을 보완하는 연속적인 구조로 설계되어 있습니다.

```text
[ 프라이버시 모델의 계층적 진화 및 통제 강도 ]

     $k$-익명성 (Anonymity) ─────► $l$-다양성 (Diversity) ─────► $t$-근접성 (Closeness)
     - 준식별자의 동일 집합화       - 민감 정보의 다양화         - 분포의 유사성 제어
     - 연결 공격 방어               - 동질성 / 배경지식 공격 방어   - 쏠림 / 유사성 공격 방어
```

---

### (1) k-익명성 (k-Anonymity)

① 핵심 개념 및 설계 규칙
* 주어진 데이터셋 내에서 준식별자(QID)들의 속성 값이 완전히 동일한 레코드 집합(이를 동등 클래스, Equivalence Class라 함)의 크기가 최소한 k개 이상이 되도록 보장하는 안전 모델입니다.
* 데이터셋에서 임의의 레코드를 추출하더라도 동일한 결합 조건을 만족하는 사람이 적어도 k명 이상 존재하므로, 외부 정보와의 연결 공격을 시도할 때 대상을 특정할 확률을 최대 k1 이하로 낮춥니다.

```text
[ $k$-익명성 ($k=3$) 변환 데이터 구조 매핑 예시 ]

         ┌──────────┬──────────┬──────────┬────────────────────────────┐
         │  우편번호 │   연령   │   성별   │    민감 질환 (Sensitive)   │  ② k-익명성의 한계 및 치명적 취약성
* 동질성 공격 (Homogeneity Attack): 동등 클래스 내부의 k개 레코드들이 가명처리는 완벽히 만족했으나, 정작 숨겨야 할 민감 정보(질환 등)가 모두 동일한 질환으로만 통일되어 있는 경우, 공격자는 확률적 추론 없이 대상을 100% 암 환자로 특정해 낼 수 있습니다.
* 배경지식 공격 (Background Knowledge Attack): 공격자가 타깃 대상의 사생활 정보나 신체 조건 등의 사전 배경 지식을 이미 보유하고 있는 경우, 동등 클래스 내의 질병 종류 중 타깃과 상관없는 옵션을 하나씩 소거하여 대상을 재식별해 냅니다.

---

### (2) l-다양성 (l-Diversity)

① 핵심 개념 및 설계 규칙
* k-익명성이 가진 동질성 공격 취약점을 해결하기 위해 제안되었습니다.
* 서로 동일한 준식별자 값을 가지는 각각의 동등 클래스 내부에서, 민감한 속성(Sensitive Attribute)의 값들이 서로 다른 종류로 최소한 l개 이상의 상이한 값을 포함하도록 강제 제어하는 모델입니다.

Each Equivalence Class contains at least l distinct sensitive values.

② l-다양성의 세부 적용 수학 법칙
* 지배적 값 제거 규칙(Entropy ldiversity): 클래스 내 민감 속성의 엔트로피(Entropy)가 최소 log(l) 이상이 되도록 규제하여 가치가 특정 고정값에 쏠리는 것을 수치적으로 차단합니다.
* Recursive (c,l)diversity: 가장 빈번히 등장하는 빈도의 지배적 민감 질병 값이 나머지 희귀한 질병들의 발생 빈도의 합에 상수 c를 곱한 값보다 작게 설정하여, 특정 질병이 과도하게 쏠리지 않도록 통제합니다.③ l-다양성의 잔존 한계와 취약성
* 쏠림 공격 (Skewness Attack): 특정 희귀 암의 전체 데이터 발생 비율이 $1%에불과한데,특정클래스내부에서이질환의비율이다양하게쪼개어져분포되다가$50%까지 치솟는 경우, 그 클래스의 대상은 원래보다 극도로 위험한 암 환자로 강하게 추론될 수 있습니다.
* 유사성 공격 (Similarity Attack): 민감 속성의 값이 문자적으로는 다양하게 쪼개져서 다양성 l 조건을 만족했으나, 정작 그 성질이 모두 위암, 간암, 폐암 등 '암'이라는 상위 카테고리 범주에 속해 유사한 경우, 공격자는 "이 클래스 내의 대상은 무조건 치명적인 전이성 암 환자다"라고 고차원적인 프라이버시를 손쉽게 침해할 수 있습니다.

---

### (3) t-근접성 (t-Closeness)

① 핵심 개념 및 설계 규칙
* l-다양성의 쏠림 공격 및 유사성 공격 한계점을 보완하기 위해 설계된 가장 통제력이 강력한 수학적 모델입니다.
* 임의의 동등 클래스 내의 민감 속성 분포를 추출했을 때, 이 **샘플 데이터 클래스 내부의 분포(Empirical Distribution)**와 전체 데이터셋 전체의 민감 속성 확률 분포 사이의 통계적 거리(Distance) 차이가 미리 지정한 문턱값 t 이하로 아주 가깝게 유지되도록 보장하는 규제 기법입니다.

```text
[ $t$-근접성의 수학적 확률 밀도 분포 일치 제어 ]

       확률 밀도 (p)
         ▲
         │          ┌───┐             ───► 전체 데이터셋의 민감정보 분포 (P)
         │        ┌─┘   └─┐
         │       ┌┘       └─┐         ───► 개별 동등 클래스 내부의 민감정보 분포 (Q)
         │       │  ┌───┐   │
         │       │ ┌┘   └┐  │
         │      ┌┴─┴─────┴──┴┐
         └──────┴────────────┴─────────────────► 민감 속성 스페이스 (X)
              * 통계적 거리 척도: Dist(P, Q) ② 통계적 거리 척도 수식 설계
* 두 확률 분포 사이의 거리를 계산하기 위해 일반적인 유클리디안 거리가 아닌, 분포의 누적 차이와 순서적 이동 비용을 계량화하는 EMD (Earth Mover's Distance) 또는 쿨백-라이블러 발산(Kullback-Leibler Divergence) 알고리즘을 사용합니다.

EMD(P,Q)≤t

* 비즈니스 함의: t 값이 0에 수렴할수록 개별 클래스의 정보는 전체 대중 평균 분포와 구분이 아예 불가능해지므로 프라이버시 수준은 최고조에 달하지만, 데이터의 개별 특이성이 완벽히 거세되므로 분석가 입장에서의 유용성은 최악이 되는 강력한 설계적 트레이드오프 관계를 보입니다.

빅데이터는 현대 산업과 사회 구조를 근본적으로 뒤흔들며 단순한 기술적 도구를 넘어 새로운 생산 요소이자 통치 기제로 자리 잡았습니다. 맥킨지(McKinsey)가 주창한 가치 창출 메커니즘과 사회 주체별 영향력은 다음과 같이 정의됩니다.

### (1) 맥킨지(McKinsey)의 빅데이터 가치 창출 5대 방식

* 투명성 제고: 전사 데이터의 실시간 동기화를 통해 비효율적 정보 격차를 완전히 거세하고 최적의 신속 의사결정을 지원합니다.
* 시뮬레이션을 통한 실험: 가상 공간의 시뮬레이션을 돌려 가설을 검증함으로써 제품 설계 R&D 리스크와 오차율을 획기적으로 낮춥니다.
* 고객 세분화 및 맞춤 서비스: 초개인화 타겟팅 기법을 구현하여 고객 만족도와 잔존율(Retention)을 극대화합니다.
* 최적 의사결정 지원: 머신러닝 예측 기반 알고리즘을 도입하여 인적 자원 배분과 물류 공급망(SCM)의 운영 효율을 고도화합니다.
* 비즈니스 모델 혁신: 전에 없던 지능형 비즈니스 플랫폼 모델과 신제품을 창출합니다.

## 2. 빅데이터의 가치 산정이 극도로 어려운 3대 본질적 이유 (★ 초빈출)

일반적인 유형 자산(기계, 부동산 등)과 달리, 데이터는 회계학적으로 명확한 감가상각이나 독립적 가치 산정이 사실상 불가능합니다. 그 본질적인 3대 한계 요인은 다음과 같습니다.

```text
[ 빅데이터의 가치 측정이 어려운 3대 메커니즘 ]

       ┌───────────────────────────────────────────────────────────────────────┐
       │  1. 데이터 활용 방식의 다변화 (Multipurpose Use)                       │
       │    - 한 목적에 쓰인 데이터가 융합·재가공되어 새로운 제3의 가치 창출    │
       ├───────────────────────────────────────────────────────────────────────┤
       │  2. 가치 창출 주체의 다변화 (Value Creator Diversification)            │
       │    - 원천 데이터 생산자(소비자)와 실질적 이익 창출자(기업)의 괴리       │
       ├───────────────────────────────────────────────────────────────────────┤
       │  3. 결합 및 융합 시너지의 기하급수성 (Synergy through Fusion)           │
       │    - 이종 데이터의 결합 시 가치가 산술적 합을 넘어 지수함수적으로 증가 │
       └───────────────────────────────────────────────────────────────────────┘
```

### (1) 데이터 활용 방식의 다변화 (Multipurpose Use)

원리: 데이터는 한 번 사용한다고 닳아 없어지는 비고갈성 자산입니다. 초기 목적(예: 포털 검색 질의어 축적)과 무관하게, 사후적으로 독감 유행 예측이나 패션 트렌드 예측과 같은 완전히 새로운 비즈니스 가치를 재창출하는 데 끊임없이 재사용됩니다.
* 가치 산정 한계: 사후에 어떤 융합 시나리오로 쓰일지 미리 예측하여 화폐 단위의 가치를 선반영하는 것이 물리적으로 불가능합니다.

### (2) 가치 창출 주체의 다변화 (Value Creator Diversification)

* 원리: 모바일 기기와 사물인터넷(IoT)을 통해 원천 데이터를 무의식중에 흘려주는 주체는 일반 '개인(소비자)'이지만, 이를 기계적으로 가공·분류하여 상업적 목적(예: 정밀 표적 광고)으로 조 단위의 부를 일궈내는 최종 주체는 거대 'IT 플랫폼 기업'입니다.
* 가치 산정 한계: 가치를 창출하는 데 기여한 무수한 데이터 기여도 지분 비율을 완벽히 수리적으로 분할 및 정량화할 수 없습니다.

### (3) 결합 및 융합의 무한성 (Synergy through Fusion)

* 원리: 데이터 A 단독의 가치는 거의 0에 수렴하지만, 신용카드 이력 데이터 B와 스마트폰 위치 데이터 C가 수학적으로 이너 조인(Inner Join)되는 순간 개별적인 가치의 합(A+B+C)을 아득히 초월하는 무한한 고차원의 비즈니스 컨텍스트(초정밀 행동 반경 패턴 모델)가 창출됩니다.
* 가치 산정 한계: 결합 시의 가치 폭발로 인해, 개별 이종 자산 고유의 독립적 시초 가치를 떼어내어 계량화하기가 불가능합니다.

## 3. 빅데이터 시대의 3대 위기 요인 및 제도적 통제 패러다임 (★ 단골 출제)

데이터 활용이 고도화될수록 인간의 자유와 존엄을 위협하는 3대 위험적 부작용이 수반되며, 이에 대응하기 위한 제도적 통제 방안 역시 패러다임적 전환을 맞이하고 있습니다.

3대 위기 요인구체적 현상 및 사회적 위협 매커니즘한계 및 통제 방안 (★ 필수 암기)**사생활 침해**<br>*(Privacy Invasion)** 스마트폰, CCTV, 센서의 일상화로 개인의 모든 흔적이 디지털 영구 기록(Digital Footprint)으로 전방위 박제화됩니다.<br>* 결합 기술의 고도화로 아무리 가명 조치를 해도 완전한 재식별 위협에 항상 무방비로 노출됩니다.**[동의제에서 책임제로 전환]**<br>* 수집 단계에서 개인에게 사전 동의를 강제하는 전통적 방식은 빅데이터 환경에서 실효성이 상실되었습니다.<br>* 따라서 **수집 단계 규제는 최소화**하되, 이를 활용하다 유출이나 재식별 오용을 저지른 **기업(활용자)에게 파산에 준하는 강력한 사후 법적 책임**을 지우는 방식으로 전환합니다.**책임 원칙의 훼손**<br>*(Damage to*<br>*Accountability)** 머신러닝 예측 알고리즘이 "이 사람이 미래에 우범 구역에서 범죄를 저지를 확률이 $98%다","신용이탈률이$95%다"라고 미리 정밀 추정합니다.<br>* 이 예측 정보만을 신뢰하여 금융 대출 심사를 사전 거절하거나 구금하는 등, 실제로 행위를 저지르기도 전에 불이익을 주는 초방제 사회가 도래합니다.**[결과 기반 책임 원칙 강화]**<br>* 알고리즘이나 통계적 추정치가 지목한 사전 예측적 점수만으로는 어떠한 사회적·물리적 처벌도 내릴 수 없도록 명문화합니다.<br>* 오직 개별 행위자가 **실제로 행동으로 저지른 구체적인 행위 결과에 기반해서만 규제와 법적 처벌**을 부과하도록 헌법적 무죄 추정의 대원칙을 고수합니다.**데이터 오용**<br>*(Algorithm Bias)** 인공지능 모형이 과거의 성차별적, 인종차별적 편향이 그대로 축적된 편향 왜곡 데이터셋을 학습합니다.<br>* 이후 "수학적 모델이라 공정하다"는 최면 뒤에 숨어, 취업 면접과 대학 입시에서 소수 인종과 여성 지원자를 기계적으로 지속 탈락시키는 왜곡된 블랙박스 결정을 번복 없이 반복합니다.**[알고리즈미스트 및 감사제 성문화]**<br>* 알고리즘의 동작 과정을 완전히 투명하게 통제하기 위해 알고리즘의 편향과 데이터 인풋 오류를 감시·디버깅하는 독립된 외부 전문가 그룹인 **알고리즈미스트(Algorithmist)** 제도를 전사적으로 도입합니다.<br>* 공공과 민간의 주요 의사결정 모형에 대한 주기적 알고리즘 편향 감사제를 성문화합니다.

## 4. 비즈니스 모델 캔버스 기반 5대 분석 기회 발굴 범위 (★ 핵심 기획 설계)

분석 프로젝트를 신규 기획할 때, 데이터 사이언티스트는 주먹구구식 기획을 지양하고 전통적인 **비즈니스 모델 캔버스(Business Model Canvas)의 9개 블록**을 아래와 같이 명확한 데이터 관점의 **5대 분석 기회 범위**로 전방위 확장하여 과제를 정렬해 내야 합니다.

```text
┌────────────────────────────────────────────────────────┐
             │                     IT 인프라 (IT)                     │
             │   - 실시간 트래픽 대응을 위한 자원 자동 가상화(Auto-Scale)    │
             └──────────────────────────┬─────────────────────────────┘
                                        │
           ┌────────────────────────────┼────────────────────────────┐
           │                            │                            │
 ┌─────────▼─────────┐        ┌─────────▼─────────┐        ┌─────────▼─────────┐
 │    업무 (Ope)     │        │    제품 (Prod)    │        │    고객 (Cust)    │
 │ - 고장 예측 정비  │        │ - 지능형 IoT 결합 │        │ - 라이프 타임 가치 │
 │ - SCM 리드타임 감축│        │ - 가상 R&D 단축  │        │ - 실시간 마케팅    │
 └───────────────────┘        └───────────────────┘        └───────────────────┘
                                        │
             ┌──────────────────────────┴─────────────────────────────┐
             │                   규제 및 보안 (Reg)                   │
             │   - 이상 금융 거래(FDS) 실시간 탐지 및 선제 보호        │
             └────────────────────────────────────────────────────────┘
```

* 업무 (Operation) 관점:정의: 기업 내부의 업무 효율화, 생산성 향상, 공정 제어 및 운영 비용 최소화를 정조준합니다.
* 적용 예시: 장비 사물인터넷(IoT) 센서 로그 기반 고장 예측 보전 시스템(Preventive Maintenance), 공급망 관리(SCM) 리드타임 단축 및 재고 적정성 예측.
* 제품 (Product) 관점:정의: 기업이 제공하는 서비스나 하드웨어 제품의 부가가치를 올리거나 혁신적 신제품을 창출합니다.
* 적용 예시: 일반 가전제품에 AI 탑재 및 지능형 가전 연계 서비스, 차량용 커넥티드 카 데이터 기반 자율주행 알고리즘 R&D.
* 고객 (Customer) 관점:정의: 소비자의 구매 행동을 유도하고 이탈을 방지하며 고객 생애 가치(LTV, Life-Time Value)를 극대화합니다.
* 적용 예시: 실시간 이탈 징후 감지 고객 이탈률 예측 모형, 위치 기반 초밀착 실시간 구매 쿠폰 자동 발행 푸시 시스템.
* 규제 및 보안 (Regulation & Security) 관점:정의: 사내 컴플라이언스를 만족하고 법적 규제 위험을 선제 통제하며, 보안 및 인프라의 침해를 실시간으로 방어합니다.
* 적용 예시: 카드 부정 결제 차단용 FDS(Frauds Detection System) 실시간 스코어링 모형, 마스킹 및 개인정보 비식별화 일괄 규제 감지 자동화 엔진.
* IT 인프라 (IT Infrastructure) 관점:정의: 무중단 분석 플랫폼 가동과 고속 연산 분산 처리를 위한 컴퓨팅 인프라 성능을 최적 제어합니다.
* 적용 예시: 예측 기반 클라우드 자원 Auto-Scaling 자동 제어 시스템, 전사 데이터 마이크로 아키텍처 API 실시간 통합 모니터링 대시보드.

## 📌 [1-1-1] 빅데이터의 본질과 패러다임의 변화

### (1) 데이터와 정보의 구조 (DIKW 피라미드)

* Data (데이터): 단순한 수집을 거쳐 축적된, 가공되지 않은 객관적 사실 (Ex. 마트 A에서 생수를 1,000원에 판매함)
* Information (정보): 데이터 간의 유기적 관계를 분석하여 유의미한 패턴을 도출한 것 (Ex. 마트 A의 생수가 마트 B보다 200원 저렴함)
* Knowledge (지식): 도출된 정보를 체계화하여 고유한 개인적 판단 기준 및 예측 규칙을 정립한 것 (Ex. 가장 저렴한 마트 A에서 생수를 대량 구매함)
* Wisdom (지혜): 축적된 지식에 통찰과 도덕적 가치관을 결합하여 유연하고 근원적인 해결책을 내리는 인지 단계 (Ex. 할인 주기, 배송비 등을 종합하여 최적화된 전사 생수 조달 조달 프로세스를 설계함)

### (2) 빅데이터의 본질적 특징 (5V)

* 규모 (Volume): 물리적인 데이터의 크기 폭발 (Tera, Peta, Exabyte 단위)
* 다양성 (Variety): 정형 데이터(RDB)를 넘어 반정형(XML, JSON, log), 비정형(이미지, 음성, 영상) 데이터로 확장
* 속도 (Velocity): 실시간 수집, 적재, 분석(스트리밍, 메모리 내 연산) 처리 주기 단축
* 신뢰성 (Veracity): 데이터 원천의 품질, 무결성, 정합성 확보 체계
* 가치 (Value): 비즈니스 도메인에서 도출되는 실질적 유용성 및 재무적 기여도

### (3) 데이터 패러다임의 주요 전환점

* 사후 처리에서 실시간 처리로: 배치 적재 방식에서 비동기 분산 스트리밍(Kafka, Spark)으로 진화
* 표본조사에서 전수조사로: 통계적 오차 한계를 인정하는 표본 추출을 넘어, 분산 저장 기술 발달로 실시간 전수 분석 체계 구축
* 인과관계에서 상관관계로: "왜 이 일이 발생했는가(Why)"의 인과론적 설명보다, "무슨 일이 함께 일어나는가($What$)"의 상관관계 예측 신속성에 주목

## 📌 [1-1-2] 데이터 사이언스와 조직 및 전략 거버넌스

### (1) 데이터 사이언티스트의 2대 역량 체계

* 하드 스킬 (Hard Skill): 대규모 분산 컴퓨팅(Hadoop, Spark), 수학·통계학적 검정 및 최적화 이론, 머신러닝 알고리즘 설계 능력
* 소프트 스킬 (Soft Skill): 비즈니스 모델에 대한 깊은 이해, 스토리텔링을 결합한 시각화 설득 능력, 직관적 통찰을 바탕으로 한 커뮤니케이션 능력

### (2) 전사 데이터 분석 조직의 3대 구조적 모델

* 집중형 조직: 전사 분석 인력을 하나의 중앙 컨트롤 타워 부서로 독립 구성특징: 프로젝트 우선순위 선정이 일관되나, 실무 부서(영업, 제조 등)의 현업 이슈 대응 신속성이 결여됨
* 기능형 조직: 분석 인력을 별도로 두지 않고, 각 영업부, 마케팅부 소속 인원들이 자체적으로 분석 수행특징: 부서 현업 밀착도는 극대화되나, 전사적 관점의 거버넌스와 중복 투자의 통제가 어려움
* 분산형 조직: 중앙 조직에서 통제받는 전문 분석가들을 각 현업 실무 부서로 배치(파견)특징: 일관된 거버넌스와 현업 밀착도를 동시 확보할 수 있어 가장 이상적이나, 조직 설계 및 조율 난이도가 높음

## 📌 [1-1-3] 빅데이터 플랫폼 데이터 형식 및 하둡 에코시스템

### (1) 데이터 구조 분류 및 특징

* 정형 데이터 (Structured): 스키마가 엄격히 정의되어 사전에 지정된 릴레이션 테이블에 저장되는 정제된 구조 (Ex. RDB 테이블, CSV 파일)
* 반정형 데이터 (Semi-Structured): 데이터 내부에 스키마 정보(메타데이터)가 포함되어 있으나, 행·열 형태의 릴레이션이 없는 구조 (Ex. XML, JSON, HTML)
* 비정형 데이터 (Unstructured): 정해진 규칙이나 텍스트 식별자 없이 유동적인 형태를 띠는 대용량 파일 (Ex. 음성 녹취록, 동영상 파일, SNS 이미지)

### (2) 하둡 고가용성 (HA, High Availability) 아키텍처

* Active NameNode & Standby NameNode: Active 노드가 마스터 역할을 전담하고, 장애에 대응해 Standby 노드가 대기함
* JournalNode (저널노드): Active 노드의 실시간 메타데이터 변경 이력(EditLog)을 복제·저장하여 Standby 노드와 실시간 상태를 동기화하는 컴포넌트
* ZooKeeper (주키퍼): 분산 코디네이터 역할을 수행하며 Active의 장애 발생 여부를 감지하고, 즉각 Standby를 Active로 하트비트 전환(Failover) 통제

### (3) 하둡 에코시스템의 핵심 수집·적재 컴포넌트

* Flume (플룸): 원천 웹서버들의 비정형 실시간 로그 파일들을 유실 없이 수집하기 위해 중간 트랜잭션 메모리/디스크 채널을 채택한 아키텍처
* Sqoop (스쿱): 분산 연산력을 활용하여 관계형 데이터베이스(RDB)와 하둡(HDFS) 파일 시스템 간에 데이터를 고속으로 상호 전송하는 Map-Only 기구
* Kafka (카프카): 고성능 분산 스트리밍 메시징 플랫폼으로, 토픽(Topic) 기반 비동기 발행-구독(Publish-Subscribe) 파이프라인 구축

## 📌 [1-1-4] 개인정보 비식별 조치 5대 기법 및 프라이버시 보호 모델

### (1) 개인정보 비식별 조치의 5대 기술적 기법

* 가명 처리 (Pseudonymization): 성명, 주민번호 등 유일성이 확정적인 고유 식별 정보를 다른 임의의 토큰이나 별명으로 대체하는 기법
* 총계 처리 (Aggregation): 개별적인 행(Row) 단위 레코드 값을 그대로 노출하지 않고, 전체 혹은 특정 군집의 평균값, 합산값으로 집계하는 기법
* 데이터 마스킹 (Data Masking): 식별 정보의 일부분을 특수문자(, # 등)로 채우는 은닉 기법
* 범주화 (Categorization / Suppression): 구체적인 단일 수치(Ex. 28세, 182cm)를 구간대 범주(Ex. 20대 후반, 180대)로 넓히는 기법
* 무작위화 (Data Perturbation): 데이터 고유의 통계적 정합성은 잃지 않으면서 값에 임의의 수학적 노이즈를 주입하여 식별을 방해하는 기법

### (2) 프라이버시 침해 방지 3대 수학적 통제 모델

* k익명성 (kAnonymity): 준식별자 속성(Ex. 나이, 성별, 주소)의 조합이 동일한 레코드가 동일 데이터셋 내에 적어도 k개 이상 존재하도록 범주화하여 연결 공격을 완벽히 무력화하는 기법
* l다양성 (lDiversity): k-익명성이 보장된 데이터 군집 내에서 민감한 정보(질병 정보 등)의 속성 종류가 적어도 l개 이상의 서로 다른 고른 다양성을 띠게 통제하여 동질성 공격 및 배경지식 공격을 방어하는 기법
* t근접성 (tCloseness): l-다양성이 지닌 민감 속성 값의 편중 분포(쏠림 현상) 취약성을 방어하기 위해, 전체 데이터 집합의 민감 정보 분포와 특정 군집 내 민감 정보 분포의 **수학적 거리 차이(지구이동거리, EMD)**를 t 이하로 압축 통제하는 모델

## 📌 [1-1-5] 빅데이터의 가치 영향력 및 비즈니스 모델 발굴 범위

### (1) 데이터의 화폐적 가치 산정이 극도로 어려운 3대 본질적 이유

* 데이터 활용 방식의 다변화 (Multipurpose Use): 비고갈성 자산으로서 사후에 새로운 제3의 알고리즘 융합 모델에 무한히 재사용될 여지가 존재함
* 가치 창출 주체의 다변화 (Value Creator Diversification): 원천 데이터를 무의식중에 흘리는 '소비자'와 이를 분류하여 거대한 이윤을 창출하는 '플랫폼' 간의 가치 기여 지분 분할이 불가함
* 결합 및 융합의 무한성 (Synergy through Fusion): 이종 데이터셋 간의 조인(Join) 시너지가 단순한 가치의 물리적 합을 아득히 초과하여 지수함수적으로 증가함

### (2) 3대 개인정보 보호 위기 요인에 대응하는 패러다임 변화

* 사생활 침해 ➡️ [동의제에서 책임제로 전환]: 사전 수집 단계의 요식적 사전동의 규제는 대폭 생략하되, 활용 단계에서 유출이나 재식별 오용 사고 발생 시 활용자에게 징벌적 책임을 강력히 물음
* 책임 원칙의 훼손 ➡️ [결과 기반의 책임 원칙 고수]: 미래의 우범 확률이나 인공지능 예측 점수만으로 사전에 불이익을 주는 초방제 사회를 규제하고, 오직 실제 저지른 행위적 결과에 근거해 책임을 지움
* 데이터 오용 ➡️ [알고리즈미스트 및 외부 감사제 성문화]: 인공지능 블랙박스 모형에 축적된 데이터 편향을 투명하게 디버깅하고 검증하기 위해 전문적인 알고리즘 외부 감사인인 알고리즈미스트(Algorithmist) 제도를 의무화함

### (3) 비즈니스 모델 캔버스 기반 5대 분석 기회 발굴 범위

* 업무 (Operation): 전사 내부 운영 효율화, 스마트 공정 최적 제어, SCM 재고 리드타임 예방 보전
* 제품 (Product): 서비스 및 하드웨어 가치 극대화, 지능형 커넥티드 서비스, R&D 단축 시뮬레이션
* 고객 (Customer): 라이프타임 가치(LTV) 극대화, 실시간 이탈 징후 분석, 초개인화 푸시 추천 엔진
* 규제 및 보안 (Regulation): 전사 컴플라이언스 만족, FDS(이상거래탐지), 비식별 자동화 관리
* IT 인프라 (IT Infrastructure): 무중단 플랫폼 제어, 트래픽 감지 자동 확장(Auto-Scale), API 실시간 모니터링

* 집중형 조직: 전사 분석 인력을 하나의 중앙 컨트롤 타워 부서로 독립 구성특징: 프로젝트 우선순위 선정이 일관되나, 실무 부서(영업, 제조 등)의 현업 이슈 대응 신속성이 결여됨
* 기능형 조직: 분석 인력을 별도로 두지 않고, 각 영업부, 마케팅부 소속 인원들이 자체적으로 분석 수행특징: 부서 현업 밀착도는 극대화되나, 전사적 관점의 거버넌스와 중복 투자의 통제가 어려움
* 분산형 조직: 중앙 조직에서 통제받는 전문 분석가들을 각 현업 실무 부서로 배치(파견)특징: 일관된 거버넌스와 현업 밀착도를 동시 확보할 수 있어 가장 이상적이나, 조직 설계 및 조율 난이도가 높음

## 📌 1−1−3 빅데이터 플랫폼 데이터 형식 및 하둡 에코시스템

### (1) 데이터 구조 분류 및 특징

* 정형 데이터 (Structured): 스키마가 엄격히 정의되어 사전에 지정된 릴레이션 테이블에 저장되는 정제된 구조 (Ex. RDB 테이블, CSV 파일)
* 반정형 데이터 (Semi-Structured): 데이터 내부에 스키마 정보(메타데이터)가 포함되어 있으나, 행·열 형태의 릴레이션이 없는 구조 (Ex. XML, JSON, HTML)
* 비정형 데이터 (Unstructured): 정해진 규칙이나 텍스트 식별자 없이 유동적인 형태를 띠는 대용량 파일 (Ex. 음성 녹취록, 동영상 파일, SNS 이미지)

### (2) 하둡 고가용성 (HA, High Availability) 아키텍처

* Active NameNode & Standby NameNode: Active 노드가 마스터 역할을 전담하고, 장애에 대응해 Standby 노드가 대기함
* JournalNode (저널노드): Active 노드의 실시간 메타데이터 변경 이력(EditLog)을 복제·저장하여 Standby 노드와 실시간 상태를 동기화하는 컴포넌트
* ZooKeeper (주키퍼): 분산 코디네이터 역할을 수행하며 Active의 장애 발생 여부를 감지하고, 즉각 Standby를 Active로 하트비트 전환(Failover) 통제

### (3) 하둡 에코시스템의 핵심 수집·적재 컴포넌트

* Flume (플룸): 원천 웹서버들의 비정형 실시간 로그 파일들을 유실 없이 수집하기 위해 중간 트랜잭션 메모리/디스크 채널을 채택한 아키텍처
* Sqoop (스쿱): 분산 연산력을 활용하여 관계형 데이터베이스(RDB)와 하둡(HDFS) 파일 시스템 간에 데이터를 고속으로 상호 전송하는 Map-Only 기구
* Kafka (카프카): 고성능 분산 스트리밍 메시징 플랫폼으로, 토픽(Topic) 기반 비동기 발행-구독(Publish-Subscribe) 파이프라인 구축

## 📌 1−1−4 개인정보 비식별 조치 5대 기법 및 프라이버시 보호 모델

### (1) 개인정보 비식별 조치의 5대 기술적 기법

* 가명 처리 (Pseudonymization): 성명, 주민번호 등 유일성이 확정적인 고유 식별 정보를 다른 임의의 토큰이나 별명으로 대체하는 기법
* 총계 처리 (Aggregation): 개별적인 행(Row) 단위 레코드 값을 그대로 노출하지 않고, 전체 혹은 특정 군집의 평균값, 합산값으로 집계하는 기법
* 데이터 마스킹 (Data Masking): 식별 정보의 일부분을 특수문자(, # 등)로 채우는 은닉 기법
* 범주화 (Categorization / Suppression): 구체적인 단일 수치(Ex. 28세, 182cm)를 구간대 범주(Ex. 20대 후반, 180대)로 넓히는 기법
* 무작위화 (Data Perturbation): 데이터 고유의 통계적 정합성은 잃지 않으면서 값에 임의의 수학적 노이즈를 주입하여 식별을 방해하는 기법

### (2) 프라이버시 침해 방지 3대 수학적 통제 모델

* k익명성 (kAnonymity): 준식별자 속성(Ex. 나이, 성별, 주소)의 조합이 동일한 레코드가 동일 데이터셋 내에 적어도 k개 이상 존재하도록 범주화하여 연결 공격을 완벽히 무력화하는 기법
* l다양성 (lDiversity): k-익명성이 보장된 데이터 군집 내에서 민감한 정보(질병 정보 등)의 속성 종류가 적어도 l개 이상의 서로 다른 고른 다양성을 띠게 통제하여 동질성 공격 및 배경지식 공격을 방어하는 기법
* t근접성 (tCloseness): l-다양성이 지닌 민감 속성 값의 편중 분포(쏠림 현상) 취약성을 방어하기 위해, 전체 데이터 집합의 민감 정보 분포와 특정 군집 내 민감 정보 분포의 **수학적 거리 차이(지구이동거리, EMD)**를 t 이하로 압축 통제하는 모델

## 📌 1−1−5 빅데이터의 가치 영향력 및 비즈니스 모델 발굴 범위

### (1) 데이터의 화폐적 가치 산정이 극도로 어려운 3대 본질적 이유

* 데이터 활용 방식의 다변화 (Multipurpose Use): 비고갈성 자산으로서 사후에 새로운 제3의 알고리즘 융합 모델에 무한히 재사용될 여지가 존재함
* 가치 창출 주체의 다변화 (Value Creator Diversification): 원천 데이터를 무의식중에 흘리는 '소비자'와 이를 분류하여 거대한 이윤을 창출하는 '플랫폼' 간의 가치 기여 지분 분할이 불가함
* 결합 및 융합의 무한성 (Synergy through Fusion): 이종 데이터셋 간의 조인(Join) 시너지가 단순한 가치의 물리적 합을 아득히 초과하여 지수함수적으로 증가함

### (2) 3대 개인정보 보호 위기 요인에 대응하는 패러다임 변화

* **사생활 침해 ➡️ [동의제에서 책임제로 전환]**: 사전 수집 단계의 요식적 사전동의 규제는 대폭 생략하되, 활용 단계에서 유출이나 재식별 오용 사고 발생 시 활용자에게 징벌적 책임을 강력히 물음* **책임 원칙의 훼손 ➡️ [결과 기반의 책임 원칙 고수]**: 미래의 우범 확률이나 인공지능 예측 점수만으로 사전에 불이익을 주는 초방제 사회를 규제하고, 오직 실제 저지른 행위적 결과에 근거해 책임을 지움* **데이터 오용 ➡️ [알고리즈미스트 및 외부 감사제 성문화]**: 인공지능 블랙박스 모형에 축적된 데이터 편향을 투명하게 디버깅하고 검증하기 위해 전문적인 알고리즘 외부 감사인인 **알고리즈미스트(Algorithmist)** 제도를 의무화함

### (3) 비즈니스 모델 캔버스 기반 5대 분석 기회 발굴 범위

* 업무 (Operation): 전사 내부 운영 효율화, 스마트 공정 최적 제어, SCM 재고 리드타임 예방 보전
* 제품 (Product): 서비스 및 하드웨어 가치 극대화, 지능형 커넥티드 서비스, R&D 단축 시뮬레이션
* 고객 (Customer): 라이프타임 가치(LTV) 극대화, 실시간 이탈 징후 분석, 초개인화 푸시 추천 엔진
* 규제 및 보안 (Regulation): 전사 컴플라이언스 만족, FDS(이상거래탐지), 비식별 자동화 관리
* IT 인프라 (IT Infrastructure): 무중단 플랫폼 제어, 트래픽 감지 자동 확장(Auto-Scale), API 실시간 모니터링

**← 클릭하여 정답 및 해설 확인**
* 정답: ④
* 해설:*Wisdom (지혜)**은 축적된 지식을 바탕으로 깊은 이해와 통찰을 통해 미래를 예측하거나, 다각적인 변수(배송비, 포인트 적립 등)를 종합적으로 고려하여 유연하고 창의적인 판단을 내리는 최고 수준의 인지 단계입니다.

## Q2. [데이터 형식] 다음 중 구조적 관점에 따른 데이터 유형 분류와 그 대표적인 예시의 연결이 올바르게 짝지어진 것은?

## Q3. [지식경영 SECI] 다음 중 데이터 지식경영의 SECI 모델에서 암묵지(Tacit Knowledge)가 형식지(Explicit Knowledge)로 전환되는 단계에 속하며, 개인의 노하우나 경험을 매뉴얼 또는 문서 형태로 구체화하는 과정을 의미하는 것은?

① 공통화 (Socialization)② 표출화 (Externalization)③ 연결화 (Combination)④ 내면화 (Internalization)

**← 클릭하여 정답 및 해설 확인**
* 정답: ②
* 해설:*표출화 (Externalization)**는 언어나 문장으로 표현하기 어려웠던 개인의 숙련된 경험과 직관적인 노하우(암묵지)를 설계서, 기획서, 매뉴얼 등 누구나 쉽게 읽고 이해할 수 있는 체계적인 형태(형식지)로 표현하여 문서화하는 과정을 의미합니다.

* ④ 내면화는 형식지 → 암묵지 단계로, 조직에 축적된 문서와 교육 매뉴얼을 개인이 학습하고 실천하여 스스로의 완전히 새로운 체화된 능력으로 흡수하는 단계입니다.

## Q9. [HDFS 분산 저장] 하둡 분산 파일 시스템(HDFS) 아키처에 대한 설명 중 가장 타당하지 않은 것은?

① HDFS는 하나의 대용량 파일을 기본 128MB 단위 크기의 블록(Block) 단위로 물리적으로 잘게 쪼개어 여러 분산 데이터 노드에 나누어 저장한다.② 하드웨어 오동작으로 인한 데이터 유실을 완벽히 복구하기 위해, 기본적으로 동일한 데이터 블록 복제본을 최소 3벌 이상(Replication Factor=3) 생성하여 복제본이 서로 다른 랙(Rack) 구조에 걸쳐 분산 저장되도록 통제한다.③ **NameNode**는 데이터 클라이언트의 요청 시 실제 데이터 블록을 로컬 물리 디스크에 실시간으로 기록하고 지우는 로컬 물리 입출력 작업을 직접 수행하는 중심 주체이다.④ HDFS는 마스터-슬레이브(Master-Slave) 구조를 가며, 마스터 역할을 수행하는 NameNode는 단일 장애점(SPOF)으로 작동할 수 있는 위험이 있어 현실적으로 이중화(Active-Standby) 시스템을 구축하여 제어한다.

**← 클릭하여 정답 및 해설 확인**
* 정답: ③
* 해설:*NameNode (네임노드)**는 분산 파일 시스템의 마스터로서, 실제 블록의 데이터를 저장하거나 물리 입출력을 대행하지 않습니다. 대신 어떤 파일이 몇 개의 블록으로 이루어져 있고 해당 블록들이 어떤 슬레이브 서버에 보관되어 있는지에 대한 메타데이터(지도 정보)만을 메모리에서 관리합니다.
* 실제 사용자 데이터 파일 블록을 물리 로컬 디스크에 영구히 저장하고 직접 입출력을 처리하며 수정한 뒤 결과를 마스터에게 보고하는 주체는 **DataNode (데이터노드)**입니다.
* ①, ②, ④는 HDFS 아키처의 분산 스케일 아웃 메커니즘을 온전히 설명하고 있습니다.

## Q10. [프라이버시 보호 모델] 다음 중 데이터셋의 개인정보 비식별 조치 수행 후, 재식별 가능성을 차단하기 위해 적용하는 프라이버시 보호 모델의 진화와 한계에 대한 설명으로 가장 적절하지 않은 것은?

① k-익명성(k-Anonymity) 모델은 동일한 준식별자(나이, 성별, 우편번호) 조합을 가진 레코드가 최소 k개 이상 존재하게 통제함으로써 결합 공격을 방어할 수 있으나, 동일 동질 집단 내 사람들의 민감 속성(질병 등)이 전부 일치할 때 발생하는 '동질성 공격(Homogeneity Attack)'에 매우 취약하다.② l-다양성(l-Diversity) 모델은 k-익명성의 취약점을 보완하기 위해 동일 준식별자 그룹 내부의 민감 속성 종류가 최소 l개 이상의 다양한 고유값을 가지도록 의무화하여 동질성 공격을 방어할 수 있다.③ l-다양성(l-Diversity) 모델은 민감 정보 종류가 다양하게 섞여 있더라도 민감 속성값이 특정 질병이나 극단적 부유층 등의 수치로 심하게 쏠려 있을 때 유추해 내는 '쏠림 공격(Skewness Attack)' 및 상호 유사한 범위 내의 값들을 악용하는 '유사성 공격(Similarity Attack)'을 원천 차단하기에는 한계가 있다.④ t-근접성(t-Closeness) 모델은 l-다양성의 한계를 완벽히 해결하기 위해 동질 그룹 내 민감 속성의 범위가 반드시 이웃한 그룹의 민감 속성 범위와의 상대적 편차 임곗값 t 이하가 되도록 물리적 거리를 격리하여 데이터의 정보 손실과 왜곡을 최소화하는 원리이다.

**← 클릭하여 정답 및 해설 확인**
* 정답: ④
* 해설:*t-근접성 (t-Closeness)**의 핵심 작동 원리는, 비식별 처리된 동질 집단 내 민감 속성의 확률 분포가 데이터셋 전체 모집단의 민감 속성 확률 분포와의 통계적 차이(EMD, Earth Mover's Distance 등)를 임곗값 t 이하가 되도록 제한하는 것입니다.
* 이 기법은 전체 분포와 일치되도록 가상의 데이터 왜곡이나 범주화를 강력하게 부여하므로, 재식별 공격 시나리오를 가장 철저히 차단할 수 있는 강점이 있는 반면, 데이터의 통계적 왜곡과 정보 유실량이 세 가지 모델 중 가장 크다는 명확한 단점을 가집니다. 따라서 "정보 손실과 왜곡을 최소화한다"는 설명은 t-근접성의 본질적인 한계와 배치되는 치명적인 오류입니다.
* ①, ②, ③은 k-익명성, l-다양성, t-근접성 모델의 탄생 배경, 인과관계, 취약점을 정확히 고밀도로 설명하고 있습니다.
