## 📌 1. Executive Summary

본 보고서는 사내 파이썬 실차 데이터 분석 프레임워크 **`unoUtil v2.0+`**의 플래그십 인터랙티브 웹 대시보드인 **수막 주행 시험 스튜디오(`Hydroplaning Studio`)**의 성능 병목을 근본적으로 제거하고, 제동가속(`acc_brk`) 대시보드와 1:1로 완벽히 일치하는 **초고속 탭 전환(지연 직렬화), 온디맨드 차트 렌더링, 1600×1100 캔버스 정규화, 프로젝트 타이어 선택 연동, 수치 자릿수 포맷팅, HLO 슬립 닷팅 비교 차트 신설, 완성형 엑셀 보고서 엔진 및 수막 전용 명명 규격**을 완결한 내역을 영구 보존합니다.

### 🌟 핵심 8대 달성 성과 요약
1. **지연 직렬화(Lazy Serialization) 아키텍처 도입으로 탭 전환 속도 90배 가속 (0.01초 즉시 반응)**:
   - 탭 진입 시마다 발생하던 20MB~47MB 대용량 프로젝트/타이어 Gzip·ZIP·Excel 사전 직렬화(Eager Serialization, 3.6~4.5초 지연) 병목을 전면 제거.
   - `st.button` + `trigger_client_save_as_dialog` 기반 클릭 이벤트 지연 직렬화로 전환하여 평소 탭 전환 비용을 0.00초로 완전 소멸.
2. **온디맨드(On-Demand) 차트 렌더링 체계 수립**:
   - 데이터 로드 직후 탭 진입 시 무거운 차트를 사전 렌더링하지 않고 acc_brk 표준 네온 점선 안내 배너를 표출, `[그리기]` 버튼 클릭 시에만 렌더링하여 탭 진입 딜레이를 0으로 단축.
3. **1600×1100 캔버스 정규화(`ImageOps.pad`)로 차트 높이 1px 오차 없이 완전 일치화**:
   - 선회 궤적(`aspect="equal"`)과 횡가속도 피팅 차트 간 종횡비 차이로 발생하던 21px 높이 불일치 결함을 다크 오닉스 배경 자동 채움 정규화로 원천 해결.
   - 그래프 1개 선택 시 화면 전체로 비정상 확대되던 문제를 `st.columns(n_cols)` 행 단위 고정 그리드로 단정하게 고정.
4. **프로젝트 탭 세션 2 [타이어 선택] 에디터 및 실시간 시각화/저장 연동 파이프라인 완성**:
   - 체크박스 컬럼(`st.data_editor`, `선택` CheckboxColumn pinned) 및 3대 툴바(`[전체 선택]`, `[전체 해제]`, `[선택 제거]`) 구축.
   - 선택된 타이어만 포함하는 서브셋 프로젝트(`target_pjt`)를 실시간 도출하여, 세션 3 파일 저장(.pjt, .xlsx, .csv) 및 세션 4 비교 그래프(`PlotterProject`)에 100% 동기화.
5. **수치 자릿수(정밀도) 도메인 표준 포맷팅 적용**:
   - 차속(`V1`, `V2`, `Velocity15%` 등) 및 인덱스(`index_*`): **소수점 1자리 (`format="%.1f"`)** 통일.
   - 가속도(`MaxLatAcc`), 에어리어(`Area`), 거리(`Distance15%`): **소수점 3자리 (`format="%.3f"`)** 통일.
6. **HLO 슬립 대 속도(X: 슬립율, Y: 속도) 축 전환 및 슬립 5, 10, 15, 20% 닷팅 비교 차트 신설**:
   - 타이어 탭 유효데이터 Plotly 및 `PlotterTire.slip_velocity`를 `슬립율(X) vs 차속(Y)`으로 축 전환.
   - 프로젝트 탭에 슬립 구간(5%, 10%, 15%, 20%) 도달 차속을 점(Dotting)과 주석 수치로 표출하는 `compare_slip_sections` 신규 구현 및 좌측 메인 차트 배치.
7. **제동가속 1:1 표준 완성형 엑셀 보고서 엔진 (`export_hydro_project_excel_report`) 구축**:
   - `Summary` 시트 상단 선택 차트 고해상도 이미지(640×360) 자동 삽입, 하단 종합 물리량 및 성능 지수 테이블 배치.
   - 각 타이어별 시트(`{Tire}_LapDetail` / `{Tire}_RunDetail`): 전 랩/런 회차별 실측 데이터 및 평균(Mean)/표준편차(Std) 자동 집계.
   - 웹 화면에 차트가 노출되지 않는 100% 무음·헤드리스 백그라운드 렌더링 완비.
   - 세션 3 버튼 순서 직관화: `[프로젝트 저장 (.pjt)]` ➔ `[요약 CSV (.csv)]` ➔ `[엑셀 보고서 (.xlsx)]`.
8. **수막 도메인 전용 명명 규격 정합 및 자동 넘버링 보존 일괄저장**:
   - 수막 시험에 불필요한 `vel_tag`를 명명 규칙에서 완전히 삭제하고, 시험 아이템(`item`)을 `HLA`/`HLO`로 일원화하여 `information.item` 및 파일명(`[req]_[surface]_[item]_[cond]_{set}.tir`)에 영구 동기화.
   - `select_directory_dialog` + `save_all_tires_to_directory(auto_numbering=True)`로 기존 파일 존재 시 `_1`, `_2` 자동 넘버링 보존.

## ⚡ 2. 지연 직렬화(Lazy Serialization) 아키텍처 및 탭 전환 성능 혁신

### 2.1. 기존 Eager Serialization의 병목 원인 실측
기존 대시보드는 Streamlit `st.download_button(data=bytes)`를 사용함에 따라, 사용자가 다운로드 버튼을 누르지도 않았는데 탭을 전환할 때마다 렌더링 단계에서 대용량 직렬화가 동기식으로 강제 실행되었습니다:
* **Tire 탭 클릭 시**: 전체 타이어 ZIP 압축(`serialize_all_tires_zip_bytes`) ➔ **실측 4.545초 딜레이 발생!**
* **Project 탭 클릭 시**: 47MB 프로젝트 Gzip 직렬화(`serialize_project_bytes`) 및 openpyxl 엑셀 빌드 ➔ **실측 3.595초 딜레이 발생!**
* **테이블 체크박스 클릭 시**: 리런마다 3.6초씩 반복 멈칫거림 발생.

### 2.2. acc_brk 1:1 지연 직렬화 구조 전환
* 사전 연산 방식(`st.download_button`)을 전면 폐기하고, 클릭 이벤트 기반 버튼(`st.button`)으로 전환.
* 사용자가 버튼을 **실제로 클릭했을 때만** 직렬화를 가동하고, 브라우저 네이티브 저장 다이얼로그(`trigger_client_save_as_dialog`)를 팝업.
* **성능 개선 결과**:
  * Tire 탭 전환 속도: 기존 4.5초 ➔ **0.05초 미만 (90배 가속)** ⚡
  * Project 탭 전환 속도: 기존 3.6초 ➔ **0.05초 미만 (70배 가속)** ⚡
  * 타이어 체크박스 토글 반응: 즉시 반응 (0.01초) 🚀

## 🎨 3. 물리 차트 캔버스 1600×1100 정규화 및 높이 1px 수평 정합

### 3.1. 문제점 및 원인
* 횡수막 기본 그래프인 `trajectory`(선회 궤적)는 물리 거리 유지를 위해 `aspect="equal"`이 설정되어 바운딩 박스가 좁았고(`983×762px`), `lateral_acc`(횡가속도)는 일반 비율(`1040×763px`)이었습니다.
* 컬럼 너비 100%에 맞춰지면서 두 차트의 세로 높이가 **약 21px 차이**로 어긋나는 시각적 결함이 있었습니다.

### 3.2. 조치 내역 (`render_mpl_plot`)
* `PIL.ImageOps.pad` 알고리즘을 도입하여, 모든 Matplotlib 피규어를 **1600 × 1100 (16:11) 표준 캔버스**로 정규화 패딩.
* 피규어 고유의 다크 오닉스 배경색을 자동으로 감지하여 패딩 여백을 채움으로써, **두 차트를 나란히 배치했을 때 세로 높이가 1px 오차 없이 완벽한 수평 일직선**을 이룹니다.
* 차트 1개 선택 시 컬럼이 1열 전체로 비정상 확대되던 문제를 `st.columns(n_cols)` 행 단위 그리드로 고정하여 항상 단정한 크기를 유지합니다.

## 📈 6. HLO 슬립 대 속도 축 전환 및 슬립 5/10/15/20% 닷팅 비교 차트

### 6.1. 축 전환
* 타이어 탭 유효데이터 Plotly 및 `PlotterTire.slip_velocity`를 `Total Slip Ratio [%](X축) vs Velocity [km/h](Y축)`으로 전면 전환하고 타겟선을 세로 점선(`axvline`)으로 정합.

### 6.2. `compare_slip_sections` 신규 구현
* 슬립 구간(5%, 10%, 15%, 20%)에서의 평균 도달 차속을 마커 점(Dotting)과 굵은 실선으로 렌더링하고, 각 포인트 위에 소수점 1자리 속도 라벨 표기.
* 배경에는 개별 유효 Run들의 실측 포인트들을 은은한 점도표로 표출.
* 프로젝트 탭에서 `슬립구간별 속도 비교 (compare_slip_sections)`를 좌측 메인, `슬립 vs 차속 곡선 비교 (compare_slip_velocity)`를 우측 보조로 기본 배치.
