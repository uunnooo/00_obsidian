# ⚠️ [미해결 현안] 웨더 탭 기상 마스터 DB 로드 및 텍스트 입력창 상호작용 먹통 이슈 분석

> **작업 일시**: 2026-11-24 화요일  
> **대상 모듈**: `unoUtil.vehicle_test.acc_brk.dashboard.tabs.tab_weather` (`dashboard/tabs/tab_weather.py`)  
> **상태**: ⏳ **이따가 작업 재개 예정 (인수인계용 현안 보고서)**

---

## 🚨 1. 현재 사용자 경험 증상 (Symptoms)

1. **텍스트 입력창 무반응**:
   - 웨더 탭의 `마스터 기상 데이터베이스 파일 경로 (.pkl.gz)` 입력창에 사용자가 임의의 경로나 파일명을 타이핑하고 엔터를 쳐도, 화면에 아무런 반응이나 데이터 로드가 발생하지 않음.
2. **[불러오기] 버튼 클릭 시 먹통**:
   - 기본 경로가 화면에 떠 있는 상태에서 [불러오기] 버튼을 누르거나, 경로를 바꾸고 눌러도 기상 데이터(114,912건)가 로드되지 않고 하단에 여전히 "상단에서 기상 DB를 불러오거나..." 안내 상자만 유지됨.
   - 단, [파일 찾기]를 누르고 드래그앤드랍 창에 직접 마스터 파일을 끌어놓는 방식에서는 백엔드 파싱이 정상적으로 수행되었음 (파싱 직후 알림 배너 렌더링 중 `NameError: html`이 났던 것은 `engine.py`에서 패치 완료됨).

---

## 🔍 2. 오늘 규명 및 조치된 사항

1. **`NameError: name 'html' is not defined` 해결**:
   - `engine.py` L1145 `_render_auto_dismiss_alert` 함수 내부 `import html` 보강 완료.
2. **`dashboard/tabs/__init__.py` 순정 파이썬 임포트 원복**:
   - 임시로 도입되었던 동적 디스패치 래퍼를 완전히 걷어내고, 순수 PEP 8 `from .tab_* import render_tab_*` 체계로 100% 클린 원복 완료.
3. **위젯 세션 키 직접 수정 버그 차단**:
   - `st.session_state["input_weather_db_path"] = ...` 직접 수정으로 인한 `StreamlitWidgetAlreadyInstantiatedError` 방어를 위해 `_pending_weather_db_path` 대기열로 정리.
4. **엄격한 지정 폴더 탐색 범위 제한**:
   - 사용자가 폴더를 지정한 경우, 오직 해당 폴더 직하(`*.pkl.gz`, `*.pkl`)만 탐색하고 엉뚱한 전역 기본 폴더로 임의 폴백하지 않도록 격리 완료.

---

## ❓ 3. 왜 여전히 텍스트 입력창과 [불러오기]가 안 먹히는가? (미해결 추적 포인트)

사용자께서 지적하신 **"실제 지금 그 id가 불러오기 버튼이 맞아? 텍스트 입력창에 입력을 했을 때 변화가 없다... 어떤 값을 넣어도 그냥 파일 로드가 안 되는 느낌인데?"**에 대한 3대 의심 원인:

1. **위젯 렌더링 위치 및 세션 상태 바인딩 불일치**:
   - `tab_weather.py`의 `w1` 컬럼에 선언된 `st.text_input`의 `key="input_weather_db_path"`가 상단 L180 부근의 초기화 로직(`_w_db_default`)과 엉켜서, 실제 사용자의 입력 이벤트가 백엔드로 올바르게 도달하지 못하고 이전 세션 상태로 되돌아가는 현상이 남아있는지 확인 필요.
2. **탭 컨테이너(`st.tabs`) 내부 버튼 이벤트 소실**:
   - `tab_w_load` 탭 컨테이너 안에서 `st.button("불러오기", key="btn_load_weather_master_db")`를 클릭했을 때, Streamlit의 탭 렌더링 주기와 버튼 클릭 플래그의 소멸 타이밍 문제로 `if btn_load_weather_db:` 블록이 실행되지 않고 스킵되는지 확인 필요.
3. **실제 실행 스크립트와 호출 경로의 완전한 분리 검증**:
   - `dashboard_app.py`가 구동될 때 `tab_weather.py`의 `render_tab_weather` 함수 내부로 진입하는지 터미널 콘솔 로그(`print` / `logger.info`)로 실시간 트래킹 필요.

---

## 🚀 4. 이따가 작업 재개 시 최우선 조치 가이드

1. **입력창 및 버튼 콘솔 직접 로깅**:
   - `render_tab_weather` 함수 시작 부분과 `w_db_path_in`, `btn_load_weather_db` 직후에 `print(f"[DEBUG] input: {w_db_path_in}, btn: {btn_load_weather_db}")`를 삽입하여 터미널에서 실제 값이 변하는지 1차 확인.
2. **텍스트 인풋 + 버튼 단일 폼 또는 독립 콜백 리팩토링**:
   - `tab_load.py`의 계측 데이터 로더 방식(위젯 세션 키 단일 분리 및 명확한 액션 함수 분리)을 1:1로 벤치마킹하여 복잡한 세션 복사 로직 전면 간소화.
3. **기본 경로 자동 로드 버튼과 수동 경로 분리 테스트**:
   - "기본 경로로 바로 로드" 버튼과 "입력 경로로 로드" 버튼의 동작을 단순 분리하여 어디서 막히는지 격리 검증.
