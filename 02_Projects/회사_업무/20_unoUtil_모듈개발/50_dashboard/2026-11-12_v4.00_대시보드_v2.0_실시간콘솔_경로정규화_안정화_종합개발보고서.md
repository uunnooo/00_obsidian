# 🖥️ 가감속/제동(acc_brk) 대시보드 v2.0 실시간 콘솔 스트리머·경로 정규화 및 런처 안정화 종합개발보고서

본 문서는 `unoUtil.vehicle_test.acc_brk.dashboard` 도메인의 통합 인터랙티브 웹 대시보드(`dashboard_app.py`, 8,800+ 라인)에 대해 **실시간 콘솔 스트리머(`StreamlitLiveConsole`) 심각도 정밀 판정 및 4색 상태 체계 탑재**, **웹 드래그앤드롭 업로드 배치 추출 및 데이터 경로 정규화 엔진 고도화**, **분석 실행 스피너/콘솔 컨테이너 슬롯 분리 및 속도 대역 미검출 안내 가이드 강화**, 그리고 **PyCharm IDE 디버거 및 다중 플랫폼 런처(`launch_dashboard`) 안정화**를 달성한 전 과정을 체계적으로 기록한 종합 기술 개발 보고서입니다.

---

## 📌 1. 개발 배경 및 목적

`unoUtil v2.0` 리팩토링 및 `unoUtil.vehicle_test` 패키지 승격에 맞추어, 가감속/제동 대시보드는 8,800여 줄의 완결된 실차 텔레메트리 스튜디오로 도약하였습니다. 실무 운영 및 현장 검증 과정에서 도출된 핵심 개선 사항들은 다음과 같습니다:

1. **실시간 콘솔 스트리밍 가시성 및 심각도 판정 개선**:
   - 기존 콘솔 스트리머는 에러 키워드만을 단순 검색하여, WARNING 메시지에 포함된 단어로 인해 잘못된 ERROR 뱃지가 표출되거나 경고 상황이 정상(COMPLETED)으로 소멸하는 문제 해결 필요.
2. **웹 업로드 및 로컬 텍스트 경로 입력 간의 상태 불일치 해소**:
   - 사용자가 브라우저 드래그앤드롭으로 업로드한 임시 스테이징 파일과 직접 텍스트 박스에 입력한 로컬/네트워크 경로 간의 전환 시, 메타데이터 파싱이 꼬이거나 이전 업로드 시그니처가 잔존하는 현상 차단.
3. **분석 실행 중 UI 렌더링 겹침 방지 및 친절한 에러 가이드**:
   - `st.spinner`와 `StreamlitLiveConsole`이 동일 슬롯에서 경쟁하여 콘솔 창 레이아웃이 밀리는 문제를 분리하고, 실제 계측 차속이 설정 속도 구간에 도달하지 않아 데이터가 0건으로 끝나는 경우 친절한 조치 가이드 제공.
4. **PyCharm 디버그 모드 서브프로세스 기동 안정성**:
   - IDE 디버거(`pydevd`)가 자식 프로세스 명령줄에 디버거 DLL을 강제 주입하여 Streamlit 서버가 무응답 멈춤(Hang)에 빠지는 현상 원천 차단.

## 🖥️ 2. 실시간 콘솔 스트리머 (`StreamlitLiveConsole`) 심각도 고도화

### 2.1. 4단계 정밀 로그 라인 분류기 (`_classify_line`)
로그 문자열 내부의 정규 표현식 및 시그니처를 기반으로 로그의 심각도(`warning` | `error` | `success` | `info`)를 판정하는 정적 메서드를 도입하였습니다.

```python
@staticmethod
def _classify_line(line: str) -> str:
    """개별 로그 라인의 심각도('warning' | 'error' | 'success' | 'info')를 판별합니다."""
    # WARNING 로그 본문에 '(Error: ...)' 등이 포함되더라도 경고 레벨이 우선되도록 먼저 판정
    if (
        "[⚠️" in line
        or re.search(r"\b(WARNING|WARN|UserWarning|DeprecationWarning|RuntimeWarning|FutureWarning)\b", line)
        or "경고:" in line
    ):
        return "warning"
    if (
        "[❌" in line
        or re.search(r"\b(ERROR|CRITICAL|FATAL)\b", line)
        or line.startswith("Traceback")
        or re.search(r"\b[A-Za-z_]\w*(?:Error|Exception):", line)
        or "치명적" in line
    ):
        return "error"
    if "SUCCESS" in line or "✔" in line or "성공" in line:
        return "success"
    return "info"
```

### 2.2. 다이내믹 4색 상태 체계 및 콘솔 유지 방어선
상태에 따라 콘솔 창의 보더, 헤더 라인, 뱃지 색상이 실시간으로 전환됩니다:
- **`ERROR`** (빨간색 `#EF4444` / 뱃지 `ERROR`): 치명적 예외, Traceback 감지 시.
- **`WARNING`** (노란색 `#FACC15` / 뱃지 `WARNING`): 휠 채널 결측, 경고 발생 시.
- **`STREAMING`** (하늘색 `#38BDF8` / 뱃지 `STREAMING`): 정상 실행 스트리밍 중.
- **`COMPLETED`** (연두색 `#A3E635` / 뱃지 `COMPLETED`): 성공적 종료 시 (에러/경고 없을 때 0초 만에 자동 소멸).
- **콘솔 유지 방어선**: 실행 중 오류(`has_error`) 또는 경고(`has_warning`)가 1건이라도 발생하면 창이 닫히지 않고 유지되어 사용자가 전체 로그 전문을 직접 확인할 수 있습니다.

## 📁 3. 파일 업로드 및 데이터 경로 정규화 엔진

### 3.1. 최신 배치 추출 및 경로 정규화
Streamlit `file_uploader`에서 드래그앤드롭 시 이전 업로드 파일과 현재 선택된 폴더 내 파일이 섞이지 않도록 최신 업로드 배치를 분리 추출하고 경로 토큰을 정규화합니다.
- `_extract_latest_upload_batch`: 복수 파일 업로드 목록 중 가장 최근에 추가된 배치 그룹만 선별.
- `_normalize_uno_upload_relpath`: 웹 업로드 시 자동 부여되는 디렉터리 구분자(`__UNO_DIR__` 등)를 표준 경로 구분자로 정규화.
- 하위 폴더(`parts > 2`)는 건너뛰고 선택한 폴더 직하위의 유효 로우 데이터(`.vbo`, `.vbb`, `.d7d`, `.dwd`, `.csv` 등)만 정밀 필터링.

### 3.2. 수동 경로 ↔ 업로드 상태 완벽 동기화
사용자가 텍스트 입력창에서 로컬 경로(예: `D:/test_data/...`)를 직접 수정하거나 비웠을 경우:
- 이전 업로드 서명(`_last_raw_upload_sig`)을 즉각 무효화.
- 임시 스테이징 디렉터리 상태를 해제하고 사용자 입력 경로를 기준으로 프로젝트 메타데이터(요구사항, 노면, 시험항목, 차속 구간)를 재파싱.
- `_pending_lc_meta_override` 큐를 통해 다음 렌더링 사이클에서 텍스트 위젯 값이 덮어써지지 않고 안전하게 보존되도록 동기화.

## ⚡ 4. 실행 컨테이너 슬롯 분리 및 가이드 강화

### 4.1. 스피너 슬롯과 콘솔 슬롯 분리
기존 `st.spinner(...)` 내부에 `StreamlitLiveConsole`이 직접 배치되어 발생하던 CSS 렌더링 간섭을 해결하기 위해, 상단 스피너 전용 컨테이너(`spinner_slot`)와 하단 독립 콘솔 슬롯(`term_placeholder`)을 분리 배치하였습니다:
```python
spinner_slot = st.container()
term_placeholder = st.empty()
with spinner_slot:
    with st.spinner(f"계측 데이터 분석 수행 중... [속도: {eff_v0} → {eff_v1} km/h | 아래 실시간 콘솔을 확인하세요]"):
        with StreamlitLiveConsole(term_placeholder, title=f"계측 데이터 분석 콘솔 [{eff_v0}→{eff_v1} km/h]"):
            # 엔진 연산 및 실시간 파이참 원본 로그 스트리밍
            ...
```

### 4.2. 속도 대역 미검출 (`all_empty`) 시 친절한 원인/조치 가이드
계측 데이터는 정상 로드되었으나 사용자가 지정한 시험 속도 대역(예: 100→5 km/h)에 실제 주행 구간이 존재하지 않아 검출 런이 0건일 경우, 단순 빈 화면 대신 원인과 해결책을 담은 공식 안내 경고문을 출력합니다:
- **원인 안내**: 계측 원본 데이터의 실제 주행 속도가 설정한 시작 속도에 도달하지 않았거나 종료 속도까지 감속되지 않음.
- **해결 안내**: 시작 속도와 종료 속도를 실제 주행 대역(예: 80→5, 60→5 등)으로 조절 후 재실행하도록 유도.

## 🚀 5. 서브프로세스 런처 (`launch_dashboard`) 안정화

### 5.1. PyCharm 디버거 몽키패치 해제
PyCharm 디버그 모드(`pydevd`) 실행 시 메모리에 주입된 자식 프로세스 생성 후킹을 해제하여, IDE 디버그 환경에서도 Streamlit 서브프로세스가 안전하게 단독 기동되도록 구현:
```python
# PyCharm 디버그 모드(pydevd) 실행 시 CreateProcess/Popen 후킹 해제
if "_pydev_bundle.pydev_monkey" in sys.modules:
    sys.modules["_pydev_bundle.pydev_monkey"].undo_patch_thread_modules()

import _winapi
if hasattr(_winapi, "original_CreateProcess"):
    _winapi.CreateProcess = _winapi.original_CreateProcess
```

### 5.2. 새 PC 환경 Streamlit 이메일 프롬프트 방어
외부 PC나 새 머신에서 최초 실행 시 터미널에서 이메일 입력(`Email: `)을 무한정 대기하여 프로세스가 멈추는 현상을 방지하기 위해, `~/.streamlit/credentials.toml` 파일의 자동 생성 방어선을 탑재하였습니다.
