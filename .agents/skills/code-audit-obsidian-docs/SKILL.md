# 🛡️ 코드 품질 점검 & 옵시디언 매뉴얼 이중 동기화 스킬 (Code Audit & Obsidian Docs)

이 스킬은 파이썬 프로젝트의 코드 품질을 체계적으로 점검하고, 사용자 승인 하에 안전하게 개선하며, 로컬 및 옵시디언 볼트에 고품질 매뉴얼을 이중 동기화하는 엔지니어링 표준 절차입니다.

---

## 📌 핵심 원칙 (Core Principles)

1. **치명적 에러 무관용 (Zero-Tolerance for Fatal Errors)**:
   - 문법 에러, 런타임 예외, 파일 스트림 누수, 직렬화 실패 등 치명적 결함은 발견 즉시 원천 수정합니다.
2. **사전 리포트 및 승인 (Report-First Approval Workflow)**:
   - 리팩토링 및 구조적 개선 사항은 독단적으로 수정하지 않고, 반드시 **[점검 레포트]** 형태로 먼저 작성하여 사용자에게 보고하고 승인을 받은 후 착수합니다.
3. **닥스트링(Docstring) 완전성**:
   - 모든 공개 함수, 클래스, 메서드에 상세 닥스트링(기능 설명, Args, Keyword Args, Returns, Raises, Examples)을 반드시 기술합니다.
4. **자가 구동 `__main__` 예제 (# region 구획화)**:
   - 외부 파일이나 데이터베이스가 없는 환경에서도 즉시 실행해 볼 수 있도록 **더미/합성 데이터(Mock Data)** 기반의 동작 검증 코드를 내장합니다.
   - `# region Case 1: ...` 및 `# endregion` 구획을 적용하여 IDE에서 영역별로 접고 독립 실행할 수 있도록 작성합니다.
5. **계층적 매뉴얼 이중 동기화 및 인박스 수집 (Dual Sync & Inbox)**:
   - **정식 매뉴얼**: 각 모듈 파일(`.py`) 옆에 동명의 상세 매뉴얼(`.md`)을 작성하고, **로컬 프로젝트 폴더**와 **옵시디언 볼트(`D:\00_obsidian\04_Resources\...` 또는 `02_Projects\...`)** 두 곳 모두에 표준 Frontmatter와 함께 동시 생성/동기화합니다.
   - **임시 작업 문서/메모의 인박스 수집 (`00_Inbox/`)**:
     - **작업 정리 파일/작업 일지 작성 타이밍**: 코드 수정 중간중간마다 매번 작업 일지(`WORK_STATUS.md` 등)나 정리 문서를 생성하지 않습니다. 오직 (1) 전체 작업이 완전히 종료되었을 때, (2) 오늘 작업을 마치고 내일 이어서 진행할 때, (3) 사용자가 명시적으로 '정리해줘/작업일지 작성해줘'라고 요청했을 때에만 최종 1회성으로 작성하여 인박스에 보관합니다.
     - 작업 중간 현황(`WORK_STATUS.md`), 초안 위키 노트 등은 `D:\00_obsidian\00_Inbox\`에 플랫(Flat)하게 배치합니다.
     - **하위 폴더 분류 불필요**: 인박스 내부에 별도 서브 폴더를 만들지 않고 루트 바로 아래에 수집합니다.
     - **파일명 규칙 면제**: 인박스 보관 시에는 `00_`, `10_` 넘버링을 적용하지 않고 원본 파일명 그대로 유지합니다. (향후 정식 위키/대시보드로 승격·흡수한 뒤 삭제하여 Inbox Zero 달성)

## 🛠️ 점검 5대 기준 (Audit Checklist)

| 번호 | 점검 항목 | 세부 기준 |
| :---: | :--- | :--- |
| **1** | **치명적 에러** | 문법 에러 없음, 미정의 변수/임포트 없음, 스트림 및 핸들 누수 차단 |
| **2** | **속도 및 성능** | 불필요한 반복문 배제, 지연 연산(@property 온디맨드) 활용, I/O 최소화 |
| **3** | **코드 일관성** | PEP 8 네이밍 규칙 준수, 인터페이스(`has_data`, `clear_cache` 등) 통일 |
| **4** | **사용성 & 유지보수성** | 다른 연구원이 직관적으로 호출 가능한 간결한 API, 낮은 결합도 |
| **5** | **문서화 충실도** | 상세 닥스트링 100%, `# region` 예제 100%, 상하위 위키링크 매뉴얼 완료 |

## 📂 옵시디언 연동 규격 (Obsidian Frontmatter Schema)

매뉴얼 생성 시 `D:\00_obsidian\AGENTS.md`의 표준 스키마를 준수합니다:
```yaml
---
id: "{{모듈명}}_{{YYYYMMDD}}"
title: "{{모듈명}} 상세 매뉴얼"
type: resource
category_main: 회사_업무
category_sub: 개발매뉴얼
date: YYYY-MM-DD
status: 완료
tags:
  - 회사_업무
  - unoUtil
  - 매뉴얼
project_link: "[[unoUtil]]"
---
```
